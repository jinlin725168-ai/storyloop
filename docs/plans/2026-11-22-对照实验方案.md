# 对照实验方案：StoryLoop 对比直接用 Claude Code

状态：方案，未执行。执行要花额度，须人批准预算后再跑。

## 要回答的问题

同一个需求，用 StoryLoop 做和直接让 Claude Code 做，**哪个更常交付正确的结果**？代价分别是多少钱、多少时间、人要动几次手？

目前的数据只能说明 StoryLoop 能跑通（真实变更 PASSED，护栏抽查没有违反合同的假通过），还不能说明它比不用更好。这个实验决定后续投入：
- 如果质量优势明显，转向扩面和真人试用；
- 如果优势不明显而成本更高，先做降本；
- 如果没有优势，需要重新审视定位。

## 两组

| 组 | 做法 |
|---|---|
| S（StoryLoop） | 按快速上手文档：`change --idea` → 回答澄清问题（按预先写好的"人的答案"）→ `approve`，直到 `PASSED` 或停点 |
| C（Claude Code） | 在同一个基础提交的干净克隆里，一次 `claude -p`：给出同样的需求一句话，加上同样的"人的答案"，要求实现、补测试、跑项目测试、提交。如果它提问，按同一份答案回答 |

- 两组用同一个模型（opus）、同一台机器、同样的单次墙钟上限（2 小时）。
- C 组不给 StoryLoop 的合同，因为合同本身就是 StoryLoop 的产出之一。要单独评估合同的价值，可以加 C2 组（把 S 批准的合同交给 Claude Code），见文末"可选扩展"。
- "人的答案"在实验开始前写好并冻结，两组共用，避免人的临场发挥影响结果。

## 样本（6 个）

| # | 来源 | 类型 | 隐藏 Gold |
|---|---|---|---|
| 1 | bench dogfood3（StoryLoop 自身） | 缺陷修复 | Case 已有 Gold |
| 2 | bench dogfood6 v2.3 | 缺陷修复，涉及已保存状态 | Case 已有 Gold |
| 3 | bench dogfood10 | 缺陷修复 | Case 已有 Gold |
| 4 | sqlite-utils 上游一个已合并的小功能 | 增量功能 | 上游 PR 带的测试 |
| 5 | sqlite-utils 上游一个已合并的缺陷修复 | 缺陷修复 | 上游 PR 带的测试 |
| 6 | sqlite-utils 上游一个涉及多处行为的改动 | 多行为功能 | 上游 PR 带的测试 |

4～6 要选上游合并前的提交作为基础，并确认 Gold 测试在基础提交上失败、在上游合并后通过（与 bench 校准同一规则）。挑选时避开 E～H 阶段已经做过的需求。

## 隔离

- 每次运行都用基础提交的全新克隆，Gold 测试不在树里，两组都看不到它。
- C 组的克隆里没有 `.storyloop/`，也不提供 StoryLoop 的技能。项目自己的 `CLAUDE.md` 或 `AGENTS.md` 如果有就保留，两组相同。
- 运行结束后，把候选改动保存为 diff，再在独立副本里套上 Gold 判定（复用 bench 的 `judge_gold`）。

## 指标

| 指标 | 怎么量 |
|---|---|
| 正确 | Gold 全部通过 |
| 自报通过但错误 | S：`PASSED` 而 Gold 失败；C：声称完成而 Gold 失败。这是最关键的一项 |
| 回归 | 项目原有测试是否仍全绿 |
| 人工触达 | S：触达账；C：除初始提示外，人需要额外发送的消息数 |
| 费用 / 墙钟 | S：调用账本；C：`claude -p` 输出的 cost 与耗时 |
| 测试质量（参考） | 新增测试数；把 Gold 失败的实现套上该组自己的测试，看是否能发现问题 |

## 次数与预算

每个样本每组 1 次，共 12 次运行。单次结果有偶然性，结论要当作方向信号，而不是统计显著的结果；有分歧的样本再加跑 1 次。

| 组 | 预估单次 | 小计 |
|---|---|---|
| S：bench 三例 | $25～40 | $75～120 |
| S：sqlite-utils 三例 | $9～15 | $27～45 |
| C：六例 | $3～8 | $18～48 |
| 合计 | | **约 $120～210**，墙钟约 8～12 小时（可分多个额度窗口） |

## 结论怎么用

| 结果 | 下一步 |
|---|---|
| S 正确数明显多于 C，或 C 有"自报完成但错误"而 S 没有 | 质量优势成立：扩面（第二技术栈、更多需求类型）和真人试用优先 |
| 两组正确数接近，S 贵很多 | 继续降本，并重新评估哪些门在小改动上真正起作用 |
| C 不差于 S | 暂停扩功能，重新审视定位：StoryLoop 的价值可能只在大改动或高风险改动上，需要另设实验 |
