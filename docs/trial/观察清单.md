# 试用观察清单（给 StoryLoop 维护者）

用来判定路线图 F 的退出标准："另一个人在自己的仓库从接入跑到一个需求 PASSED，人只在做决定时介入。"

## 判定

| 项 | 通过条件 | 证据 |
|---|---|---|
| 另一个人 | 试用者不是 StoryLoop 开发者，没有我们在旁边操作 | 试用者确认 |
| 自己的仓库 | 不是 sqlite-utils，也不是 StoryLoop 自身 | 反馈表 |
| 跑通 | 变更 `PASSED` 并在本地合并 | `report.md` 状态 |
| 只在决定时介入 | 触达账里每一条都是决定（确认设置、回答问题、确认缺口、批准）；续跑和修复为 0 | `touches/<ID>.jsonl` 与反馈表逐条对照 |
| 结果可信 | 试用者复核合并的改动，认为符合需求；没有发现假通过 | 反馈表"结果是否可信" |

## 记录

- 每一次非决定的触达：原因属于哪类（引擎缺陷 / 提示不清 / 环境问题 / 试用者误操作），是否已有 issue。
- 新暴露的引擎缺陷：按"先写测试再修复"处理，记入试用记录。
- 费用与耗时，与 sqlite-utils 基线（约 $9～15、15～20 分钟代理时间）对比。

## 结论写到

`docs/validation/<日期>-真人试用.md`，并更新 `docs/roadmap.md` 中 F 的状态。
