# 试用说明

感谢试用 StoryLoop。这次试用只回答一个问题：**你能不能在自己的仓库里，从接入到第一个需求合并，只在做决定时才需要动手？**

## 适合这次试用的仓库和需求

| 条件 | 要求 |
|---|---|
| 仓库 | 单个 Git 仓库，Python 项目，用 pytest 或 unittest，测试能在本机直接跑（不依赖 Docker） |
| 工作区 | 干净（无未提交改动），在具名分支上 |
| 代理 | Claude Code 已登录：`claude -p "hi"` 能返回 |
| 需求 | 一个小的增量需求，例如给命令加一个选项、给函数加一个参数。不要选缺陷修复、重构或跨多个模块的需求 |

## 预计投入

- 时间：接入约 10 分钟；需求从起草到合并约 20～40 分钟，其中大部分时间不用你看着。
- 费用：一个小需求约 $9～15 的 Claude 用量（审查约占一半）。请确认你的额度足够，额度用尽时运行会停下，等额度恢复后用 `storyloop run` 继续。
- 你的操作：顺利的话 3～4 次——确认接入设置、回答澄清问题、批准合同；准备度有缺口时多一次确认。

## 怎么开始

按 [快速上手](../quickstart.md) 的第 1～5 步操作。遇到停点时，先看输出里的"下一步"，也可以用 `storyloop inbox <项目>` 查看所有等你决定的事项。

## 已知限制

- 只在一个 Python 项目（sqlite-utils）上真实验证过，你的项目可能会遇到新问题，这正是试用要发现的。
- 护栏（"不出现假通过"）在近期改动后的复测还没有定论；请把试用当作评估，合并前照常自己看一遍改动。
- StoryLoop 只在本地提交和合并，不会 push，也不会改你的 CI 配置。
- 引擎会在项目里写 `.storyloop/`（已加入 `.git/info/exclude`，不会进入 Git）。

## 结束后

请填写 [反馈模板](反馈模板.md)，并把下面三样发给我们（都在你的项目里，不含你的代码之外的凭证）：

- `storyloop log <项目> --change <变更ID>` 的输出；
- `reports/storyloop/<变更ID>/report.md`；
- `.storyloop/state/touches/<变更ID>.jsonl`（你敲过哪些命令）。
