# StoryLoop 架构收敛阶段 E2a：代理实现通道实施计划

日期：2026-10-25。基线：`origin/main` 的 `34da20e`（E1 已合入）。本计划待评审；本 PR 只提交计划，不实现。

## 全局约束

- 沿用 E1 的 base 合同、草案、批准、补充配置、旧底座绿 G1、候选验证 G2、人工验收、FINALIZING、回执及 I8。旧合同指纹算法、旧状态文件和旧回执保持原样可读。`--implementer human` 的 E1 路径和已有在途运行保持可用。
- 合并源分支之前，任何中断、失配或代理产物异常均作废**本次尝试**的引擎中间产物，重新验证；不复用磁盘上的方案、证据、报告或审查。人提交的候选还在时回 `HUMAN_IMPLEMENTATION_REQUIRED`；代理模式下人不得向 base 分支提交，重来时在项目锁内将分支回到合同提交，清理索引及工作区中的本次代理产物，回 `CONTRACT_COMMITTED`。若出现无法归属本次代理调用的提交，停 `WORKSPACE_TAINTED` 交人处理。源分支是否已包含候选或报告提交按 Git 事实判定。合并后只用 E1 的回执、底座版本和 I8 幂等路径。手动合并的非标准历史沿用 E1 的明确人工恢复指引，不扩展自动恢复范围。
- 代理的响应、代码、测试、报告和自评均不可信。证据、审查和批准只由引擎或具名人写入并以摘要绑定 state；代理不得写 `.storyloop/`、补充配置、报告、审查、验收与判据证据。隔离与 Git 路径审计同时执行；软性提示不能充当权限边界。
- 每个任务先加失败测试，确认失败，再实现，再确认通过；每次提交前运行 `ruff check storyloop tests examples`。`tests/test_architecture.py` 零豁免，不能改 `architecture.toml` 的既定模块归属。函数尽量不超过 50 行、文件不超过 500 行；`base_execution.py` 现已约 500 行，E2a 流程放专门模块并共用 E1 入口。
- 涉及路径、分支、越权、符号链接、控制面与恢复的测试登记 `SAFETY`，纯策略登记 `FAST`，完整流程登记 `END_TO_END`；慢的不变量在 `INVARIANTS` 只登记单个测试 ID。记录每个新测试模块单独运行耗时。完成时本机 core、后台 full、ruff、PR CI 以及手动触发的 Linux/Windows 完整 core 都通过。

## 本计划作出的决定（经 PR #46 评审修订）

1. **实现者选择。** 新 base 运行默认 `agent`；显式 `--implementer human` 保留 E1。`ci`、`upstream` 默认人工，且 CI 永不交给代理；其他 scope 默认代理，可显式选人工。保存到新运行 state 后不可中途切换，以免把代理提交误当成人的提交；旧 state 缺少实现者字段按 E1 的 `human` 解释。理由：设计要求代理为默认，同时 E1 的 CI 人工授权及机械操作边界不应隐式放宽。`skills` 中 Oracle 技能确认仍由人作出。
2. **方案批准。** base 用专属的简短方案记录（目标、批准路径、实施步骤、风险与回退），由 design/implement 代理只能提出、具名人用新 `base-design-approve` 明确批准。复用 `design_approval.py` 的摘要绑定和锁内人工审批方式；不直接调用 `approve_design/current_binding`：后者在约第 30–90 行要求 routed plan、选项、suite、principles 与评估，E1 base 没有这些输入。方案摘要绑定批准合同、合同提交、源 HEAD、底座版本、引擎版本。代理开始前重新计算；方案修改或绑定失配作废本次尝试并重走方案审批，不接受旧文件。人工通道仍按 PR #40 修订跳过 design 代理与方案停点。
3. **跨厂商审查。** 以适配器握手能力中的规范化 `vendor` 判定，而非角色名、adapter 别名或模型名；缺失 vendor 视为不可证明。审查只读、由引擎调用 `review`，必须不同于本次 implement 调用的实际 vendor；不允许 `cross_vendor.policy` 的 `degrade` 回落为同厂商。引擎将通过结论、审查适配器/vendor、候选 commit/tree、合同/方案摘要和审查文件 SHA 写进 state；G2 重查绑定。fail、不可用或失配均作废本次尝试，回代理的固定重来点。E1 人审保留检查全部候选提交的作者与提交者。
4. **单代理人工替代。** 仅当项目实际可配置的 agent 适配器经握手证明只有一个 vendor 时，具名操作者可在 `base-review` 使用 `--human-review '<理由>'`、`--verdict`、`--note`。理由须非空、去空白后至少 12 个字符，且不得只是审查结论；记录 reviewer、理由、候选绑定和 `mode=human_substitute`。仍要求审查者不是任何候选提交的作者或提交者，仍经过人工验收。报告增量写 `review_mode` 与理由，指标单独计 `base_human_review_substitutions`；E1 普通 `base-review` 记 `mode=human_e1`，不计替代。多 vendor 项目审查服务不可用时 fail closed，不能借此标志绕过。
5. **判据路径留给 E2b。** E2a 不开放判据路径，继续执行 E1 的 `audit_base_scope` 拒绝规则：系统冒烟、`acceptance/changes/**`、声明的 `test_roots`、`acceptance/storyloop-settings.json` 均不得由代理修改；`.storyloop/**`、引擎证据内核及补充配置同样受保护。隔离注入跑红单独在 E2b 规划和实现，E2a 不新增探针合同、探针证据或相应状态。
6. **最重档位。** `approvals._base_approval`（约第 80 行）继续固定 `tier=heavy`；base agent 调用在 `project_agents.invoke_project_agent`/`role_profiles.role_settings` 的实际路由出口强制 `routing_tier=heavy`，拒绝角色配置降为较弱模型档，禁用分流降级、成本回退与同厂商 review fallback。测试检查实际 transport request、profile 与调用账本，不能只检查审批字段。
7. **越界处理。** 代理只获得批准的精确路径；CI、判据路径、控制面、补充配置、报告/证据与源分支始终排除。调用前在 state 保存“合同提交 + 调用前 HEAD”作为唯一重来锚点，并要求干净的 Git tree/索引；代理模式下人不得向 base 分支提交，由引擎在审计通过后生成至多一个候选提交。调用后以 `changed_paths`（`--no-renames`）、未跟踪文件、符号链接和控制面摘要审计。发现越界先停 `WORKSPACE_TAINTED`，列出路径和安全清理指引；仅当锚点之后至多一个候选提交符合引擎配置的代理作者/提交者身份、可选报告尾提交符合 E1 已有检查、且没有额外提交时，才在项目锁内回到合同提交并清理本次代理产物。出现额外提交、身份不符或归属不明时保持停点，不自动删除。禁止把代理越界 CI 文件当作 `base-propose --allow-ci` 授权。
8. **E3 边界。** E2a 不自动把 `BASE_CHANGE_REQUIRED` 的原变更接到新 base，也不更新原分支、重证其 RED 或恢复预算；这些属于 E3。E2a 只产出稳定的 base `change_id`、新版底座版本与既有回执，保持 E3 可引用的 provenance；不把 `blocked_by` 登记为已完成能力。
9. **自举。** 在 T6 引擎分离完成前，代理不得执行触及 StoryLoop 引擎、守卫、适配器或其判据的本仓库 base 变更；入口以经批准路径与实际引擎源路径判定并给出 `--implementer human`/独立旧引擎的指引。不能只靠代理提示“不要改自己”。人工 E1 通道继续可用，但不声称达到设计 §8 的固定旧引擎自举保证；T6 前不得把该保证登记为已实现。

## 新增写入链与中断点表（先测试，后实现）

每行代表一个独立故障注入点；`S` 为磁盘上最近一次已保存运行状态。所有合并前重来都不采纳残留产物。代理模式以调用前写入 state 的“合同提交 + 调用前 HEAD”为锚点：最多允许一个符合预期身份的引擎候选提交及 E1 已知的报告尾提交；确认没有额外提交后，才在项目锁内将 base 分支回到合同提交并清理本次代理产物。发现额外或归属不明的提交则停 `WORKSPACE_TAINTED`，给人工处理步骤。人工候选另走 E1 固定点。以下测试名在各 Task 落地。

| 中断位置 | 重跑看到的 S / Git 事实 | 期望行为与测试 |
|---|---|---|
| 写方案临时文件后、落正式文件前 | `CONTRACT_COMMITTED`；无可信方案 | 清理临时文件，重生方案；`test_plan_temp_interruption_restarts` |
| 写正式方案后、保存方案摘要前 | `CONTRACT_COMMITTED`；磁盘有未绑定方案 | 作废文件和尝试，重新生成并重新人批；`test_plan_write_before_state_restarts` |
| 人批准方案文件后、保存批准摘要前 | 方案停点；仅磁盘有批准 | 作废批准，必须重新具名批准；`test_plan_approval_before_state_restarts` |
| 能力握手缓存写入后、代理调用锚点保存前（实施核对补充） | `IMPLEMENTING`；握手文件已更新，尚无调用锚点 | 作废尝试，重走旧绿与方案审批；`test_capability_cache_write_before_agent_anchor_restarts` |
| 调用前锚点保存后、代理尚未运行 | `IMPLEMENTING`；state 有合同提交与调用前 HEAD，工作区仍干净 | 作废本次尝试，从合同提交重走方案与验证；`test_anchor_before_agent_call_restarts` |
| 代理已写文件、尚未形成候选提交 | `IMPLEMENTING`；工作区/索引含代理修改 | 根据调用前锚点确认归属，回合同提交并清理本次产物；`test_agent_write_before_commit_restarts` |
| 候选已暂存、提交失败 | `IMPLEMENTING`；HEAD 仍是调用前 HEAD，索引有暂存 | 清理本次代理候选的索引与工作区，回合同提交；`test_agent_staged_commit_failure_restarts` |
| 代理候选提交成功、保存 commit 前 | `IMPLEMENTING`；HEAD 比调用前 HEAD 前进 | 锁内检查合同提交之后是否只有本次代理调用的提交；是则直接回合同提交，额外或归属不明的提交停 `WORKSPACE_TAINTED`；`test_agent_commit_before_state_restarts`、`test_extra_commit_stops_tainted` |
| 候选绿色证据写入后、保存 state 摘要前 | `IMPLEMENTING`；磁盘有未绑定证据 | 作废证据与候选，回合同提交重验；`test_candidate_evidence_before_state_restarts` |
| 跨厂商审查文件写入后、保存摘要前 | `BASE_REVIEW_REQUIRED`；仅磁盘有审查（实施核对修正状态） | 作废审查及候选，重新实现与审查；`test_review_write_before_state_restarts` |
| 审查摘要已保存、G2 前任一证据/方案/代理产物失配 | `BASE_REVIEW_REQUIRED` 或 `MANUAL_ACCEPTANCE_REQUIRED`；state 摘要不符 | 作废全尝试，不能修补单文件或复用缓存；`test_review_tamper_restarts` |
| 人工验收写入后、保存摘要前 | `MANUAL_ACCEPTANCE_REQUIRED`；仅磁盘有验收 | 作废验收、审查、证据和代理候选；`test_acceptance_write_before_state_restarts` |
| 报告文件/索引/报告提交写入后、保存 VERIFIED 前 | `MANUAL_ACCEPTANCE_REQUIRED`；可能有报告提交 | 依 E1 预合并规则丢弃全部引擎提交与文件，重来；`test_report_commit_before_state_restarts` |
| `finish_feature` 已把报告并入源分支、保存 MERGED 前 | `VERIFIED`；源 ref 已含报告提交 | **不重来**，走 E1 Git 事实与回执/版本幂等路径；`test_merge_before_state_finishes_idempotently` |
| 代理候选提交后、保存候选 commit 前，源分支已被人手动合入（实施核对补充） | `IMPLEMENTING`；state 尚无 candidate_commit，但源 ref 已含 base HEAD | Git 事实优先，不删 base 候选；仅给 E1 人工恢复指引；`test_unsaved_candidate_already_on_source_cannot_be_discarded` |

实施前已核对 E1 的实际顺序：`_open_state` 先建 base 分支再 `save_run`；`_prepare` 先 materialize 合同文件，再保存 `CONTRACT_READY`，然后 `commit_paths` 合同与保存 `CONTRACT_COMMITTED`，写旧绿证据、保存摘要并通过 G1；候选验证写绿色证据后才保存候选摘要；`record_base_review` 与 `record_manual_acceptance` 均先 `write_json` 后 `save_run`；`_verified_report` 先 `write_json`/`write_text_atomic`，再 `commit_paths`，再保存 `VERIFIED`；`finish_feature` 合并后才保存 `MERGED`，之后回执和底座版本按 E1 幂等路径推进。E2a 新增的调用前锚点和候选绿色证据窗口已补到上表；代理调用的 `.storyloop` 诊断日志/账本只作审计，不作为恢复或判定证据，中断后仍按调用前锚点作废整次尝试。若实施中再出现表外窗口，先补表与故障测试。方案/审查文件不是 Git 候选提交的一部分，代理候选和报告提交也不合并保存步骤。重来操作须与 `run`、`reset`、方案批准、人工替代审查、`accept` 共用项目锁。沿用 `base_restart` 事件，但需显式增加唯一的 `(DESIGN_APPROVAL_REQUIRED, CONTRACT_COMMITTED)` 边，并把该停点纳入 `BASE_PREMERGE`：方案停点的文件被篡改时必须能整次作废。`IMPLEMENTING → DESIGN_APPROVAL_REQUIRED` 已由 `stop` 覆盖，`DESIGN_APPROVAL_REQUIRED → IMPLEMENTING` 已由 `begin_attempt` 覆盖。不得为其他局部中断新增迁移边。
