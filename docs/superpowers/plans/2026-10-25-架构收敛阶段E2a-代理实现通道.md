## 评审修订：代理独立 worktree（2026-10-26）

**已批准。** 人于 2026-10-26 批准独立 worktree 设计。第三轮审查显示，忽略规则可变、调用后清单可能缺失且未忽略的大目录可超出 Git 输出上限，因此不能从共享工作区的文件清单推断哪些文件属于代理。合并前仍整次作废重来，合并后仍仅走 E1 的 Git 事实、回执、版本及 I8 幂等路径；不采纳旧代理产物。

### 1. 位置、命名与创建锚点

- 用系统临时目录下的引擎专用根 `storyloop-agent-wt/<仓库 Git common-dir 的短摘要>/<change_id>/<随机 attempt_id>`，逐级创建为当前用户私有目录；规范化后必须位于**项目工作树之外**，路径各级不得是符号链接或 Windows reparse point。`change_id` 先按已有 ID 规则验证，`attempt_id` 用随机值，不能仅按日期/编号复用旧目录。系统临时目录可能包含测试项目，故以规范化的项目根作包含关系校验；若不满足就选择另一外部临时根，找不到则停止代理调用。路径写在 state 中，目录名只用于定位与诊断，恢复绝不按名称猜测或扫描删除。外部私有目录避开项目 `.gitignore`、IDE 项目索引与项目构建扫描；在 Windows 使用短摘要与短随机段控制路径长度。主仓库 `.git` 可能是文件，因而不假定它是可放工作树的目录。
- 在项目锁内、调用前先确认主 base 分支正位于 `contract_commit` 且索引、已跟踪及未跟踪工作区干净；如有人的未提交改动，**先停并要求人自行处理**，不写代理锚点，不清理人的文件。随后把 `agent_worktree={path, contract_commit, attempt_id}` 写入新运行的 state 并 `save_run`，再执行 `git worktree add --detach <path> <contract_commit>`。这样创建后到下一次保存状态之间崩溃，也能只按已记录锚点清理。状态只增新字段；旧 E1 state、合同指纹、回执不迁移、不重写。实际调用前核对 worktree 的 Git common-dir、注册记录及 `HEAD` 与该锚点一致；不一致停 `WORKSPACE_TAINTED`，不删除未知目录。
- detached worktree 从合同提交检出，只带 Git 跟踪文件和 Git 工作树元数据；不复制原项目的 `.venv`、`node_modules`、`.env`、忽略文件或未跟踪笔记。`agent_worktree` 是唯一可恢复锚点，不再保存 `agent_before_inventory`、`agent_after_inventory` 或全树摘要。若适配器握手在此之前更新缓存，仍按原 E2a 规则作废重来、重新握手。

### 2. 适配器执行目录与写入范围

- 拆开**原项目控制面**与**代理执行目录**：配置、能力握手、指令、账本、诊断日志、方案/批准/证据仍在原项目由引擎读写；仅实施调用的 request 中 `project`/`workspace`、进程 cwd 与可写根指向独立 worktree。不能直接用 `invoke_project_agent(worktree, ...)`，否则它会去 worktree 读取不存在的 `.storyloop/config.json`，并把账本写错地方。只对 base `implement` 增量传执行目录，不改变 feature 调用协议或原项目配置。
- command 适配器：`run_process` 的 cwd 和请求中的执行路径均为该 worktree；展开命令中的项目占位符时也使用执行目录，原项目路径不作为可写根传给代理。普通命令进程本身**没有**文件系统沙箱；需由操作者选择具备相应限制的代理 CLI 或无凭证容器包装，StoryLoop 只能约束输入、搬回路径并审计，不能声称阻止同用户进程越界。Codex：每次 base implement 均用 `exec --sandbox workspace-write -C <worktree>`，不传 `--add-dir`；当前 `codex exec resume` 无 `-C`/`--sandbox` 选项，因此 base implement 的响应格式修复不续跑原 session，而是作废该尝试并在新 worktree 发起新调用，feature 的现有续跑方式不变。响应 schema、调用账本由引擎留在原项目。增加传输层测试，断言 base implement 首次调用与格式失败后的重新调用均不把原项目作为代理工作目录或沙箱可写根。

### 3. 校验与搬回候选

- 代理返回后**先**核对引擎源码提醒、主分支/合同锚点与 worktree Git 身份，再审计。以合同提交为基准，在独立 worktree 内用 `git diff --no-renames --name-status -z <contract_commit>`（包含已提交、暂存和未暂存结果）取已跟踪变化，并用 NUL 分隔的未跟踪文件枚举补上新文件；忽略文件不搬回，最终随整个 worktree 删除。输出过大或 Git 失败视为尝试无效，仍可按 state 锚点删除 worktree；不得卡在读取完整清单才能清理。`--no-renames` 必须把重命名算作“删旧路径 + 加新路径”。
- 按合同**精确**批准路径逐一比对增加、修改和删除，仍执行 E1 `audit_base_scope`；越界、缺少应变更路径、判据/控制面/CI 禁区均作废尝试。用 `lstat`/Git tree mode 校验路径各级和最终项：不跟随符号链接或 junction，拒绝新建/修改链接、gitlink 及任意模式位变化（含可执行位）；获批准的普通文件删除允许，新增/修改须保持普通文件模式。二进制按原始字节与 Git blob OID 搬运、比较，不按文本解码或改换行；受既有大小/合同限制，若无法安全读取则作废。审计通过前绝不写主工作区。
- 再次要求主 base 分支仍是合同提交且工作区干净，由引擎把核验过的**具体内容**写到主 base 分支的批准路径，删除则只删对应路径，然后由引擎以既有代理身份 `commit_paths` 产生一个候选提交，并把提交 OID 写回 state。不得 cherry-pick 代理在 detached worktree 中的提交：代理可以伪造作者、提交者、父提交、路径与提交数量；搬回最终经批准的文件内容再由引擎提交，才能保持现有 G1/G2、独立审查和候选来源语义。搬回期间每次写入前重查目标父路径不为链接；主工作区任何意外脏状态都停止，不能覆盖人的文件。
- 搬回前可写 `transfer_paths`/阶段标记到 state 供错误指引，但**不据此推断**主工作区后来出现的改动一定属代理。若在“首个主文件写入—候选提交”窗口中断，先按锚点删除独立 worktree；主工作区若脏则保持字节原样，停 `WORKSPACE_TAINTED`，提示人检查并自行提交、移走或撤销后再 `reset`/`run`。不能自动 `restore .` 或删除未跟踪文件。候选提交完成而 state 尚未保存时，只有 Git 显示它是合同提交的单父子、改动恰为批准路径且作者/提交者为引擎身份、源分支尚未包含它、主工作区干净，才能按 E1 预合并重来把 base 分支退回合同；有额外提交或事实不明则停点交人。

### 4. 清理、重来与中断点

任何合并前中断、失配或代理越界都让这次方案/证据/审查/验收失效，锁内只根据 state 的精确 worktree 锚点执行 `git worktree remove --force <path>`，成功后 `git worktree prune`；目录不存在时核对 Git 注册记录并按已移除处理。不能按目录名、文件清单或忽略状态推断所有权。remove 失败则保持锚点和停点，绝不启动第二个 attempt；人工关闭持有文件的代理/IDE、按错误给出的**已记录路径**执行 `git worktree remove --force <path>`、`git worktree prune`，再 `storyloop reset <project> --change <id> --reason '<reason>'`。若路径/注册身份与 state 不符，保留现场，要求人工核对，不运行强制删除。主工作区的人类未提交改动始终不动；若不干净，先给出人工处理步骤。`run` 与 `reset` 共用项目锁和同一清理入口；已合并的 Git 事实优先，绝不清理或退回源分支。

下表列出**代理实现窗口**；后文表格只列方案批准、候选证据、审查、验收、报告及合并窗口。代理候选在合并前一律先清理独立 worktree，再按上述主分支规则重来。所有测试先写失败断言，再实现。

| 中断位置 | 重跑看到的 state / Git 事实 | 期望行为与故障测试 |
|---|---|---|
| 锚点保存前、创建前 | 无 `agent_worktree`；无新目录 | 主项目不变，重走握手与准备；`test_worktree_before_anchor_restarts` |
| 锚点已保存、创建命令前或执行中 | 有精确路径/合同，目录可能为空或半建 | 只核对并清理该锚点；未注册但非空未知目录停点；`test_worktree_anchor_before_add_restarts`、`test_worktree_add_interrupted_preserves_unknown_path` |
| detached worktree 创建后、代理调用前 | 已注册，HEAD 为合同提交 | remove + prune，废弃方案批准并重来；`test_worktree_add_before_invoke_restarts` |
| 代理运行中，留下已跟踪、未跟踪、忽略文件或链接 | state 仍指向本次 worktree；主项目保持干净 | 整树 remove + prune，不枚举归属、不触碰主项目；`test_worktree_agent_crash_discards_all_files` |
| 代理返回后、路径审计前；或审计发现越界/输出超限 | worktree 有任意代理内容 | 不搬回；按锚点整树清理并重来；`test_worktree_before_audit_restarts`、`test_worktree_out_of_scope_discards_attempt`、`test_worktree_large_output_can_restart` |
| 审计通过、首个主文件写入前 | 主分支仍在合同，主工作区干净 | 清理 worktree，重新调用代理，不复用已校验内容；`test_worktree_audit_before_transfer_restarts` |
| 搬回某个批准路径写入中、候选提交前 | 主 HEAD 仍在合同；主工作区可能部分脏 | 清理 worktree；**保留**主工作区全部现状，停 `WORKSPACE_TAINTED` 给人工清理步骤；`test_transfer_interrupted_preserves_main_changes` |
| 路径已暂存、候选提交失败 | HEAD 仍为合同；索引可能有批准路径 | 清理 worktree，保留主工作区/索引，停点让人处理；`test_transfer_commit_failure_preserves_main_index` |
| 候选提交成功、保存 candidate OID 前 | 主 HEAD 是合同的一个引擎候选子提交 | 清理 worktree；经 Git 事实校验且工作区干净才退回合同重新验证；否则停点；`test_transfer_commit_before_state_restarts`、`test_transfer_extra_commit_stops` |
| 清理命令失败（Windows 文件锁等） | state 仍保存原路径和 attempt | 停 `WORKSPACE_TAINTED`，给出关闭进程、精确 remove/prune/reset 命令，不复用或覆盖；`test_worktree_remove_locked_reports_steps` |
| 候选/报告合并进源分支后，清理尚未完成 | 源 ref 包含本次提交 | 不退回源或重新实现；锚定 worktree 清理失败只留下告警及待清理路径，回执/版本仍走 E1 幂等推进；`test_worktree_postmerge_cleanup_keeps_finalization` |

### 5. Windows、自举与威胁模型

- 临时根采用系统 API 而非硬编码 `/tmp`；路径段短、创建前检查规范化后的绝对路径，并在路径过长/不可创建时给明确停点。Windows 文件锁使 remove 失败时保留 state 锚点，不删注册记录、不擅自 `prune` 掉仍占用的树；人工按上表处理。新的 worktree 继承仓库 Git 配置，`core.autocrlf` 等检出/加入规则照常生效；比较以 Git blob OID 和路径状态为准，不把 CRLF 工作区字节当作候选摘要。两平台 SAFETY 测试覆盖创建、删除失败、CRLF、路径边界与符号链接能力差异。
- 仍保留“当前运行的引擎源码文件属于项目 Git 跟踪文件时拒绝 base 代理”的自举限制；项目内 `.venv` 或被忽略的 site-packages 不在 detached worktree 中，正常代理写根不能直接改到它们。`engine_source_digest` 继续仅作提醒：摘要计算若遇含 surrogate 的文件名等 `UnicodeEncodeError`/其他 `UnicodeError`，记录“无法核对引擎源码，请检查并重新安装”的警告，不能阻断调用完成、重来或 `reset`；代理后发现摘要变化也只警告，不当作状态锚点。
- StoryLoop **不是沙箱**。Codex `workspace-write` 或命令适配器自己的沙箱/无凭证容器应把可写根限于 detached worktree；同用户恶意进程仍可访问原项目、`~/.gitconfig` 和共享 `.git` common-dir，这是现有威胁模型接受的残余风险。本文不宣称已隔离同用户进程，也不恢复此前回退的全局 Git 配置隔离。`docs/architecture.md` 与 `docs/api.md` 在实现任务中同步写清此边界。

### 6. 删除、保留与实施任务

- 删除 `base_agent_inventory` 及其基于调用前后文件清单、忽略规则、大小/文件数上限的归属推断，删除 `run_recovery` 中的共享工作区 `restore .`、未跟踪清理和相应测试；把第三轮“忽略规则变化、无调用后清单、未忽略大目录”三个回归测试改成**主工作区不受代理调用触碰、整树清理可重来**。保留第一轮的 vendor 规范化、握手缓存变化作废重来、`principles.json` scope 一致性、人审替代理由校验、冗余字段清理，以及第二轮中与文件归属无关的有效修复。`engine_warning` 的 Unicode 异常处理纳入本修订。
- **Task W1（锚点与创建）：** 先在 `tests/test_base_agent_worktree.py`（SAFETY）写外部位置、私有目录、同 change 多 attempt、旧 state 兼容、创建前后崩溃、未知路径不删、Windows 路径/锁失败测试，确认红；再实现 `base_agent_worktree.py` 的 state 先存、detached add、身份核对、remove/prune，确认绿。仅新增 state 字段，不改旧状态文件；提交前跑 ruff 与架构测试。
- **Task W2（调用路由）：** 先在 `tests/test_base_agent_transport.py`（SAFETY）写 command cwd/请求路径、Codex base 首次调用的 `-C`/沙箱与格式失败后不 resume、原项目账本与配置、`.venv` 不复制及自举限制测试，确认红；再分离 `project_agents` 的控制面路径与 transport 执行目录，确认绿。command 无强制沙箱能力的限制写进文档和测试预期；不改变 feature 协议。提交前跑 ruff 与架构测试。
- **Task W3（审计与搬回）：** 先在 `tests/test_base_agent_transfer.py`（SAFETY）写精确路径、重命名双端、未跟踪/忽略、二进制、删除、模式位、symlink/junction、越界、输出超限、主工作区脏及搬回中断测试，确认红；再用既有 `--no-renames` Git helper 与 `audit_base_scope` 对 detached 树审计，安全写入并由引擎生成候选提交，确认绿。任何受审计 Git 输出上限影响的尝试可失败，但清理不得依赖读取该输出。提交前跑 ruff 与架构测试。
- **Task W4（统一重来与端到端）：** 先在 `tests/test_base_agent_recovery.py`（SAFETY）改写旧清单测试并覆盖上表全部故障点、`run`/`reset` 锁内同构、主工作区不自动清理及 Git 已合并边界；在 `tests/test_base_agent_flow.py`（END_TO_END）覆盖新 worktree 的完整代理通道、人审替代与 E1 human 兼容；在 `tests/test_base_agent_policy.py`（FAST）验证提醒遇 Unicode 异常仍不阻断，均先确认红。再删旧清单与采纳分支，接回 E1 的 G1/G2、审查、验收和合并后幂等流程；更新 docs/api.md、docs/architecture.md、tests/suites.py，确认绿。每个新模块单独计时，跑本机 core/后台 full、ruff、架构零豁免、PR CI 与手动 Linux/Windows core，逐项记录。每任务各提交一次。
- 不新增状态枚举或迁移边；使用现有 `CONTRACT_COMMITTED`、`IMPLEMENTING`、`WORKSPACE_TAINTED` 与 `base_restart`，方案回退仍仅使用已批准的 `(DESIGN_APPROVAL_REQUIRED, CONTRACT_COMMITTED)`。新增的只是**新代理尝试**的 worktree 锚点和可选搬回阶段字段；旧 E1/E2a state 没有锚点时按旧在途运行兼容处理，不能猜路径删除。若实际实现确需新迁移边，按原停止条件暂停交人决定。

## 全局约束

- 沿用 E1 的 base 合同、草案、批准、补充配置、旧底座绿 G1、候选验证 G2、人工验收、FINALIZING、回执及 I8。旧合同指纹算法、旧状态文件和旧回执保持原样可读。`--implementer human` 的 E1 路径和已有在途运行保持可用。
- 合并源分支之前，任何中断、失配或代理产物异常均作废**本次尝试**的引擎中间产物，重新验证；不复用磁盘上的方案、证据、报告或审查。人提交的候选还在时回 `HUMAN_IMPLEMENTATION_REQUIRED`；代理模式仅按 state 锚点删除独立 worktree，主工作区的未提交改动一律保留，干净且可证明归属的引擎候选提交才回合同提交与 `CONTRACT_COMMITTED`。主工作区脏或出现额外提交时停 `WORKSPACE_TAINTED` 交人处理。源分支是否已包含候选或报告提交按 Git 事实判定。合并后只用 E1 的回执、底座版本和 I8 幂等路径。手动合并的非标准历史沿用 E1 的明确人工恢复指引，不扩展自动恢复范围。
- 代理的响应、代码、测试、报告和自评均不可信。证据、审查和批准只由引擎或具名人写入并以摘要绑定 state；代理不得写 `.storyloop/`、补充配置、报告、审查、验收与判据证据。隔离与 Git 路径审计同时执行；软性提示不能充当权限边界。
- 每个任务先加失败测试，确认失败，再实现，再确认通过；每次提交前运行 `ruff check storyloop tests examples`。`tests/test_architecture.py` 零豁免，不能改 `architecture.toml` 的既定模块归属。函数尽量不超过 50 行、文件不超过 500 行；`base_execution.py` 现已约 500 行，E2a 流程放专门模块并共用 E1 入口。
- 涉及路径、分支、越权、符号链接、控制面与恢复的测试登记 `SAFETY`，纯策略登记 `FAST`，完整流程登记 `END_TO_END`；慢的不变量在 `INVARIANTS` 只登记单个测试 ID。记录每个新测试模块单独运行耗时。完成时本机 core、后台 full、ruff、PR CI 以及手动触发的 Linux/Windows 完整 core 都通过。

## 本计划作出的决定（经 PR #46 评审修订）

1. **实现者选择。** 新 base 运行默认 `agent`；显式 `--implementer human` 保留 E1。`ci`、`upstream` 默认人工，且 CI 永不交给代理；其他 scope 默认代理，可显式选人工。保存到新运行 state 后不可中途切换，以免把代理提交误当成人的提交；旧 state 缺少实现者字段按 E1 的 `human` 解释。理由：设计要求代理为默认，同时 E1 的 CI 人工授权及机械操作边界不应隐式放宽。`skills` 中 Oracle 技能确认仍由人作出。
2. **方案批准。** base 用专属的简短方案记录（目标、批准路径、实施步骤、风险与回退），由 design/implement 代理只能提出、具名人用新 `base-design-approve` 明确批准。复用 `design_approval.py` 的摘要绑定和锁内人工审批方式；不直接调用 `approve_design/current_binding`：后者在约第 30–90 行要求 routed plan、选项、suite、principles 与评估，E1 base 没有这些输入。方案摘要绑定批准合同、合同提交、源 HEAD、底座版本、引擎版本。代理开始前重新计算；方案修改或绑定失配作废本次尝试并重走方案审批，不接受旧文件。人工通道仍按 PR #40 修订跳过 design 代理与方案停点。
3. **跨厂商审查。** 以适配器握手能力中的规范化 `vendor` 判定，而非角色名、adapter 别名或模型名；缺失 vendor 视为不可证明。审查只读、由引擎调用 `review`，必须不同于本次 implement 调用的实际 vendor；不允许 `cross_vendor.policy` 的 `degrade` 回落为同厂商。引擎将通过结论、审查适配器/vendor、候选 commit/tree、合同/方案摘要和审查文件 SHA 写进 state；G2 重查绑定。fail、不可用或失配均作废本次尝试，回代理的固定重来点。E1 人审保留检查全部候选提交的作者与提交者。
4. **单代理人工替代。** 仅当项目实际可配置的 agent 适配器经握手证明只有一个 vendor 时，具名操作者可在 `base-review` 使用 `--human-review '<理由>'`、`--verdict`、`--note`。理由须非空、去空白后至少 12 个字符，且不得只是审查结论；记录 reviewer、理由、候选绑定和 `mode=human_substitute`。仍要求审查者不是任何候选提交的作者或提交者，仍经过人工验收。报告增量写 `review_mode` 与理由，指标单独计 `base_human_review_substitutions`；E1 普通 `base-review` 记 `mode=human_e1`，不计替代。多 vendor 项目审查服务不可用时 fail closed，不能借此标志绕过。
5. **判据路径留给 E2b。** E2a 不开放判据路径，继续执行 E1 的 `audit_base_scope` 拒绝规则：系统冒烟、`acceptance/changes/**`、声明的 `test_roots`、`acceptance/storyloop-settings.json` 均不得由代理修改；`.storyloop/**`、引擎证据内核及补充配置同样受保护。隔离注入跑红单独在 E2b 规划和实现，E2a 不新增探针合同、探针证据或相应状态。
6. **最重档位。** `approvals._base_approval`（约第 80 行）继续固定 `tier=heavy`；base agent 调用在 `project_agents.invoke_project_agent`/`role_profiles.role_settings` 的实际路由出口强制 `routing_tier=heavy`，拒绝角色配置降为较弱模型档，禁用分流降级、成本回退与同厂商 review fallback。测试检查实际 transport request、profile 与调用账本，不能只检查审批字段。
7. **越界处理。** 代理在项目工作树外的 detached worktree 实施；调用前 state 保存精确 worktree 路径、合同提交与 attempt ID，主 base 分支及工作区必须干净。代理返回后在该树中用 `--no-renames` 和未跟踪路径枚举审计，按批准的精确路径、安全类型与 Git blob 逐一校验；CI、判据、控制面、补充配置及报告/证据路径均不得搬回。引擎只把合格内容写到干净的主 base 分支并提交一个候选。越界作废并按锚点整树删除；主工作区脏、额外提交或身份不明时停 `WORKSPACE_TAINTED`，保留人的改动，给人工步骤。不能把代理越界 CI 文件当作 `base-propose --allow-ci` 授权。
8. **E3 边界。** E2a 不自动把 `BASE_CHANGE_REQUIRED` 的原变更接到新 base，也不更新原分支、重证其 RED 或恢复预算；这些属于 E3。E2a 只产出稳定的 base `change_id`、新版底座版本与既有回执，保持 E3 可引用的 provenance；不把 `blocked_by` 登记为已完成能力。
9. **自举。** 在 T6 引擎分离完成前，代理不得执行触及 StoryLoop 引擎、守卫、适配器或其判据的本仓库 base 变更；入口以经批准路径与实际引擎源路径判定并给出 `--implementer human`/独立旧引擎的指引。不能只靠代理提示“不要改自己”。人工 E1 通道继续可用，但不声称达到设计 §8 的固定旧引擎自举保证；T6 前不得把该保证登记为已实现。
