# 子项目 5：分层记忆 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 出过问题的变更在收尾时产生经验草案；人批准后按强度落地；下一个相关变更自动把经验送到对的角色面前，报告能对照"提供了什么 / 代理声称用了什么"；知识库错误可以随时勘误。

**Architecture:** 新增七个小模块，各管一件事：`lessons`（条目格式与校验，纯函数）、`lesson_store`（从提交读取、冻结摘要、新鲜度、`lessons` 命令）、`lesson_retrieval`（筛选、排序、注入载荷、声称校验）、`drafts`（统一草案目录）、`lesson_landing`（`approve --draft` 按强度落地与回滚，含 check 的先证明会红）、`errata`（勘误校验、草案、`errata.md`）、`retrospective`（问题信号、复盘调用、复发统计）。现有模块只改调用点：`project_agents._invoke_once` 注入与记录，`project_loop_finish.finalize_change` 收尾后触发复盘，`report_presentation` 第 6 节换成真实内容。

**Tech Stack:** Python 3.11 标准库；测试用 `unittest`，命令 `.venv/bin/python -m unittest ...`，从仓库根目录运行。

**Spec:** `docs/superpowers/specs/2026-10-19-子项目5-分层记忆-design.md`（Q1–Q10 均按推荐；§15 是写计划时的四处修正，以 §15 为准）

## Global Constraints

- 只用标准库，Python 3.11+；不新增依赖。
- 经验文件：`openspec/lessons/L-<四位以上数字>.md`；元数据块以 `---` 行起止，每行 `键: JSON 值`；正文 ≤ 4096 字节；核心层（`tier: "core"` 且 `status: "active"`）正文合计 ≤ 4096 字节。
- `summary` ≤ 120 字符；`lessons_used[].how` ≤ 200 字符；每次复盘最多 3 条经验提议。
- 普通层取用最多 10 条，只给 `id`、`summary`、`path`、`status`；核心层带正文、不占名额。
- 排序：`active` 先于 `needs-review`；同状态内 `prose` > `knowledge` > `check` > `config`；再按 `updated_at` 降序。
- 作用范围语义：每项用 `path_security.forbidden_path_root` 规范化（精确路径或末尾 `/**`），另允许字面量 `"**"` 表示全仓库；匹配规则 `path == root or path.startswith(root + "/")`。
- 新边界类别 `LESSON_PROTECTED`（`openspec/lessons/**`）。
- 草案目录：`.storyloop/drafts/lesson/<draft-id>/`、`.storyloop/drafts/errata/<draft-id>/`；`draft-id` = `D-<来源变更ID>-<两位序号>`（手动或非变更来源用 `D-manual-<UTC 时间戳 YYYYMMDDHHMMSS>-<两位序号>`）。现有变更草案与 `drafts/smoke/` 不迁移。
- 经验 ID 在**审批时**分配（现有最大号 + 1，四位补零），草案里不占号；`update`/`retire` 提议引用已有 ID。
- 复盘：角色 `review`，`payload.mode = "retrospective"`，只读；失败或到成本上限不改变 `PASSED`。
- `config` 强度审批一律拒绝，提示改为 prose 并人工改配置。
- 新命令：`drafts PROJECT [--reject KIND/ID --reason R]`、`lessons PROJECT [--confirm ID | --retire ID --reason R]`、`lessons-propose PROJECT --change ID`；`approve PROJECT --draft KIND/ID`。现有 `approve PROJECT --change ID` 不变。
- 报告第 6 节「记忆」：无经验目录时 `item('memory', reason='LESSONS_NOT_CONFIGURED')`；措辞"代理声称使用"，不写"已读"。
- 兼容：无 `openspec/lessons/` 时不注入 `payload.lessons`、行为不变；旧运行状态无 `lessons_digest` 时续跑补算；已提交的报告与回执不重写。
- 函数尽量不超过 50 行；新文件不超过 500 行；面向用户的文字用中文，代码与标识符用英文。
- 提交信息 `type(scope): 中文主题`，作者用仓库身份，不加 Co-Authored-By。

## Review Focus

1. **Windows 上手工编辑过的经验文件**：带 BOM、CRLF 换行。期望照常解析，ID 与正文不带 `\r`（Task 1 的 `test_crlf_and_bom_are_accepted`）。
2. **两个草案都要新建条目**：先后批准，不能分到同一个 ID 或覆盖文件。期望第二个分到下一个号（Task 6 的 `test_two_create_drafts_get_consecutive_ids`）。
3. **人把草案改坏后再批准**：期望拒绝，工作区、HEAD、配置、BASE 提案目录与批准前逐字节一致（Task 6 的 `test_invalid_edited_draft_leaves_no_trace`）。
4. **代理声称用了没提供的条目**：不能拒绝回答，也不能计入"已使用"。期望记为 `lessons_unknown`，报告标出（Task 4 的 `test_unknown_claim_is_recorded_not_rejected`）。
5. **变更运行中途有人批准了新经验**：这次运行看到的经验不能变。期望取用从合同提交读，且有运行进行中时 `approve --draft` 被拒绝（Task 2 的 `test_lessons_are_read_from_contract_commit_not_worktree`，Task 6 的 `test_landing_refused_while_a_run_is_in_progress`）。
