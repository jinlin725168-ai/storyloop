# 需求共创技能 第 1 批：spec-craft 技能包 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付一个随引擎打包的 `spec-craft` 技能，人可以在 Claude Code、Codex 的对话里调用它，完成评估、需求、规格、澄清四步，产出两份人能读懂的 Markdown（需求文档、规格文档），再交给现有的 `storyloop change --idea`。

**Architecture:** 技能是 `storyloop/skills/spec-craft/` 下的一组 Markdown（`SKILL.md` 加 `references/`），沿用现有的打包与 `storyloop skills` 安装机制。frontmatter **不写 `roles`**，所以引擎不会把它下发给任何角色，命令行入口完全不变。结构由 `tests/test_spec_craft.py` 的确定性测试守住；内容效果用一次真实对话试用来验证，并记录下来。

**Tech Stack:** Markdown；Python 3.11 标准库 `unittest`（只用于结构测试）；现有 `storyloop/skills.py`。

**Spec:** `docs/superpowers/specs/2026-10-23-需求共创技能-design.md`（第 1 批，§13；内容要求见 §5–§7、§9.1）

## Global Constraints

- 不修改 `storyloop/` 下任何 `.py` 文件，不改 CLI、合同格式、状态格式；只新增技能包、测试和文档。
- `storyloop/skills/spec-craft/SKILL.md` 的 frontmatter 只有 `name`、`version`、`description` 三个键，**不得有 `roles` 或 `stacks`**（设计 §9.4：最后一批之前，不把两套说法同时下发给同一个角色）。
- 技能包只含 `.md` 文件：`pyproject.toml` 的 `package-data` 只打包 `skills/**/*.md`。
- 技能正文用中文；`description` 同时写中文和英文的触发说法（与 `foundation-survey` 一致）。
- 技能中所有"由人拍板"的事项照抄设计 §7.3，不得改成由 AI 决定。
- 规格层的行类型直接引用 `oracle-craft` 的验收矩阵（`storyloop/skills/oracle-craft/references/acceptance-matrix.md`），不另写一份。
- 不引入第三方依赖。
- commit 格式 `<type>(<scope>): <subject>`，中文；只用仓库用户身份，不加 Co-Authored-By trailer。

## 本计划作出的决定（实现前请评审）

1. **第 1 批的产出是两份 Markdown，而不是合同 JSON。** 设计 §13 写的是"按现有 product v1 合同结构产出草稿"，但现在没有导入合同文件的命令（`--from-draft` 属于第 3 批）。在对话里写一份没人能接收的 JSON 没有意义。所以第 1 批产出需求文档和规格文档，由人用 `storyloop change --idea "$(cat <目录>/requirements.md <目录>/spec.md)"` 交给现有流程，再由 product 角色转成合同。
2. **覆盖地图写成 `references/clarify.md` 里的表格**，不建 `assets/coverage.csv`。CSV 不会被打包；数据化和定制合并放在第 2 批。
3. **草稿目录是目标项目的 `.storyloop/drafts/spec/<slug>/`**，与设计 §10 一致，第 3 批的 `--from-draft` 可以直接沿用。
4. **版本从 `1.0.0` 开始。**

## Review Focus

1. 同一个项目里装了 spec-craft，命令行的 product 角色**收不到**它：`select_skills(root, "product", [])` 不包含 `spec-craft`。→ Task 1 `test_spec_craft_reaches_no_engine_role`。
2. `SKILL.md` 提到的每个参考文件都真实存在，`references/` 里也没有未被提到的文件，否则对话里的代理会去找不存在的文件，或者漏读文件。→ Task 1 `test_skill_md_links_every_reference_and_nothing_else`。
3. 在已初始化的项目上运行 `storyloop skills`，会因为新增技能而开出一个 BASE 提案，不会静默写入底座。→ Task 1 `test_install_on_initialized_project_proposes_spec_craft_files`。
4. 技能总大小在引擎下发上限之内（`MAX_SKILL_BYTES = 200_000`）。第 5 批要把它下发给 product 角色，到那时超限会直接报错。→ Task 1 `test_spec_craft_fits_the_delivery_limit`。
5. 模板里的"由人拍板"和"最多 3 处、最多 5 个问题、一次一个"这些硬约束，写错了数字或者被删掉，技能就悄悄变了。→ Task 2、Task 3、Task 4 中对这些原文的断言。
