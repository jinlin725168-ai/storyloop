> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `storyloop metrics PROJECT` 把各变更留下的报告、运行状态、变更记录与调用账本汇总成 12 组指标、按规则给出带证据的调整建议和延后项信号；`ci --record` 让"本地绿、CI 红"有数据可算。只读，不改规则。

**Architecture:** 五个新模块，数据单向流动：`metrics_collect`（读取并归一化每个变更为一条记录，冲突入 `discrepancies`）→ `metrics_compute`（M1–M12 纯函数）→ `metrics_rules`（R1–R12 与延后项信号，纯函数）→ `metrics_render`（Markdown）；`metrics` 负责编排、`--since`、`--save`。`ci --record` 只在 `smoke_runner.run_ci` 的 CLI 出口加一个写文件步骤。

**Tech Stack:** Python 3.11 标准库；测试用 `unittest`；单模块 `.venv/bin/python -m unittest tests.<module> -v`，全量 `.venv/bin/python tests/run.py --suite full`（若 #8 尚未合入则用 `-m unittest discover -s tests -t .`）。

**Spec:** `docs/superpowers/specs/2026-10-19-子项目6-外环-design.md`（Q1–Q8 均按推荐）

- 只用标准库，Python 3.11+；不新增依赖。
- `metrics` 只读：除 `--save` 写的 `reports/storyloop/metrics/<YYYY-MM-DD>.md` 与 `.json` 外不写任何文件、不调用代理、不要求工作区干净、不提交。
- 取数优先级：有 `reports/storyloop/<ID>/report.json` 的变更以它为准，运行状态只补它没有的字段；同一字段两处不一致时以报告为准，并在 `discrepancies` 记 `{change_id, field, report, run}`。

- 每项指标输出：`{"id", "value", "numerator", "denominator", "n", "changes": [ID], "missing": [{"change_id", "reason"}], "by": {...可选分列}}`；分母为 0 时 `value: null`、`reason: "NO_SAMPLE"`。
- 缺失原因码固定：`NO_SAMPLE`、`CI_RESULTS_NOT_PROVIDED`、`LESSONS_NOT_CONFIGURED`、`UNKNOWN_REPORT_VERSION`、`NO_ROUTING`、`NO_TIER_RECORDED`、`UNREADABLE`。

- 阈值默认表在代码里，`.storyloop/config.json` 的 `metrics.thresholds` 可按规则 ID 覆盖 `threshold` 与 `min_sample`；未知规则 ID 或非数值报错（`StoryLoopError`，消息含键名）。
- 面向用户的文字用中文，代码与标识符用英文；函数尽量 ≤ 50 行，新文件 ≤ 500 行。
- Windows：比较 Git 检出的文件与提交时按 Git 规则（`git hash-object`），不要逐字节；子进程文本管道显式 `encoding="utf-8"`；输出中文前 `sys.stdout` 已由 CLI 设为 UTF-8，不要另行假设。

## Review Focus

1. **被 supersede 的变更**：既有自己的运行（停在 `NEEDS_SPEC_FIX`）又被新变更取代；期望计入 M3（规格返工），不计入 M1 的分母，supersede 链在延后项信号里算长度（Task 2 的 `test_superseded_change_counts_as_rework_not_as_a_pass`）。
2. **只有运行状态、没有报告的变更**（停住或放弃的变更）：期望照样进入集合，M1b 的预算用尽、M4 的 `NO_PROGRESS` 从运行状态取到（Task 1 的 `test_stopped_change_without_report_is_collected_from_run_state`）。
3. **`.storyloop/state` 被清理过、只剩已提交报告**（换机器）：期望不报错，依赖运行状态的指标把这些变更列入 `missing`（Task 1 的 `test_reports_without_run_state_still_compute`）。
4. **`metrics.thresholds` 写错**（未知规则 ID、字符串阈值）：期望明确报错并指出键名，不静默忽略（Task 4 的 `test_invalid_threshold_override_is_rejected`）。
5. **同一变更多份 CI 结果、或结果的提交不在该变更合并之后**：期望取最新、忽略不相关提交并列入 `missing`（Task 3 的 `test_ci_results_take_latest_and_ignore_unrelated_commits`）。
