## 来源集合与迁移限制

迁移表不把所有停点视为同一种状态。必须从现有函数的控制条件派生来源集合；本表确定对应关系，执行时逐条将下面真实常量原样移入表，不扩展成员：

| 元数据 / 事件 | 基线来源 | 保持的区别 |
|---|---|---|
| runnable | project_loop._open_run 的 resumable 集合 | 不含 WORKSPACE_TAINTED；PASSED由顶部幂等返回；SUPERSEDED不能run |
| repair_red | acceptance_repair.REPAIRABLE | 只允许原列举的停止状态且有contract_commit；失败仍EXISTING_GREEN/ORACLE_DEFECT |
| reset | run_recovery.RESETTABLE 与 _reset_status | 仅WORKSPACE_TAINTED、MANUAL_ACCEPTANCE_REQUIRED；L3 planning专门恢复DESIGN_REVISION_REQUIRED |
| supersede | supersede.SUPERSEDABLE | NEEDS_SPEC_FIX可不填reason，其他状态必须理由；已合并不允许 |
| overrule | project_loop_failures.ROUTED_STOPS、require_routed_choice | 必须是已记录的审查归属或一致性归属；不能用理由绕过任意停点 |
| display_stop | stop_report.STOP_STATUSES | 原12项展示集合保留；分流三停点不能因此自动进入metrics的原统计范围 |
| cost_restore | cost_resume.stop/restore 的原阶段快照 | 来源仅COST_LIMIT_REACHED；目标来自该运行已记录阶段，不任意字符串 |
| recover_merge | project_loop._open_run + project_receipt.recover_completed_merge | 仅VERIFIED且当前源分支，核验真实merge拓扑与产物 |
| stop | 全仓pause/pause_for_boundary调用点 | 只涵盖真实会暂停的阶段及目标；无全局任意to/status后门 |

reset 的 `_reset_status`：manual→IMPLEMENTING；L3且phase=planning→DESIGN_REVISION_REQUIRED；有interrupted_status则恢复它；无中断字段且attempt=0时按contract_commit选择CONTRACT_COMMITTED/PREPARING；否则IMPLEMENTING。旧中断字段可接受性的现状不在B收紧。

cost_restore 当前只改内存，稍后由外层保存；consistency_overrule 可能先临时IMPLEMENTING、随后又停；design_approval._clear_checks 也会在调用者后续流程中保存。统一入口不等于新增中间save：必须以原顺序为准。
