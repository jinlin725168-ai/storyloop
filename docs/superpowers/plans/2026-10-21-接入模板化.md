# 接入模板化实施计划（T4）

> **For agentic workers:** Use subagent-driven-development to implement this plan task-by-task. 用户已于 2026-10-21 在会话中批准设计并要求立即实施，按全部推荐答案执行；无需重复审批。

**Goal:** 交付可生成、人工补齐、干净锁定、离线运行并保持严格 0/1/2 的接入骨架。

**Architecture:** 保留旧 init 与 manifest。新增显式 scaffold 分支、独立生成/锁定校验和可回滚初始化事务；受保护清单钉住引擎版本及 helper API。由引擎解析专用 argv 标记，使用受信解释器的隔离模式启动绝对 launcher，再加载受保护薄执行器；业务在独立子进程中运行。

**Tech Stack:** Python >=3.11，标准库，现有 processutil/path_security/storage，无新增依赖。

**Spec:** ../specs/2026-10-20-接入模板化-design.md；本次会话批准 Q1–Q7 的推荐方案。

## Global Constraints

- Maven、Node、Python、Maven+Node；Gradle/未知仅 generic，不能伪称特化支持。
- `init PATH --scaffold --stack STACK` 只生成草案，不写 baseline/config/exclude、不提交、不执行探测命令。
- 明确标“未初始化、需人工补全”；未补 hook/配置、0 用例、环境/构建/清理故障必须返回 2；真实断言失败 1、实际执行全绿 0。
- 版本钉住精确引擎版本及 helper API 主版本；不得直接信任候选路径上的同名包，不能网络 fallback。
- 路径、symlink/hardlink/reparse、scratch 归属、并发、环境白名单、日志边界按设计 §6 全部实现。
- 不做数据/SQL/鉴权、真实模型、CI配置、部署、真实 RuoYi 修改；仅公开隔离夹具。
- 单函数 <=50 行，单文件 <=500 行；测试关键行为，先 RED 再实现；不弱化已有门。

**Interfaces / rulings:**
- `scaffold_project(project: Path, stacks: list[str] | None = None) -> dict`：返回明确 scaffold 状态、栈建议/选择、生成文件和人工下一步；不完整选择退出 2。
- `validate_onboarding(project: Path, profile: dict) -> dict | None`：旧仓库无清单返回 None；有清单验证全部已批准要求，旧 init 签名不变。
- `storyloop.testing.smoke_harness.v1` 提供 case 精确验证、隔离 scratch、内容同步、受控 argv、显式健康探针、结构化计数和资源清理；具体函数签名在实现前写入该模块文档及本任务报告，最终复核接口一致。
- 新 argv 使用 `['{storyloop_harness}', 'acceptance/tools/<stack>_smoke.py', ...case_paths]`；只有引擎识别首 token，转为绝对解释器 `-I` 与绝对 launcher。旧 `{python}` 继续原样工作。
- hook 是受保护脚本中的明确阶段：build/start/ready/run_case/cleanup；不需要的阶段必须在清单声明 not_applicable 和理由。未实现阶段不能假绿。
- 源码同步只从显式安全列表读取，不扫描或读取凭证；缓存显式声明、只作依赖使用，不共享可写构建目录。
- 生成清单记录初始生成摘要用于幂等检测；补全后的执行器与版本记录在干净提交上校验并由 BASE 保护。生成摘要不得被误用成拒绝一切人工补全。
