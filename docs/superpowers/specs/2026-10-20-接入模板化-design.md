# 接入模板化设计（T4，待评审）

日期：2026-10-20。调查基线：StoryLoop `6319d83`；不依赖其他任务未合入的代码。

**状态：仅设计，所有新增接口、推荐与取舍均待用户评审；未写实施计划、未实现、未做真实接入。**
本文按架构设计处理。依用户要求一次交付方案与待决问题，评审后才进入计划阶段。

## 1. 目标与边界

目标是把一个新底座的接入工作从约两天缩短到半天，减少重复编写执行器和反复补规范的时间。
两天是需求给出的现状估计，半天是目标，均非本次测量结果。不能靠跳过测试、隐式批准或扩大可写范围缩时。

拟由 `storyloop init` 提供按技术栈生成的冒烟执行器骨架、`AGENT_GUIDE.md` 模板和 settings 草案；
将当前 vendored `smoke_harness.py` 的通用积木提升为引擎发布的能力。业务启动、就绪判定和数据隔离仍由项目声明。

非目标：自动生成业务验收断言、自动写 CI、部署、运行真实模型、自动安装依赖、修改数据库 schema 或执行建库/导数/清库、
自动扩展 Spring profile、改变鉴权设置、替项目决定目录权限。复杂服务编排、外部模板插件市场、自动迁移已有执行器延后。
不把模板完成等同于 readiness READY，也不把 T2 的未通过自然经验验收算作完成。

### 2.2 不能原样提升的 helper 行为

当前示例不是受支持的安全 API：scratch 按名称共用；复制可能根据大小/mtime 跳过；
`split_cases` 只检查存在及后缀；`wait_http` 把 HTTP 错误响应也视为就绪；`stop` 使用 POSIX 进程组；
`run_python_cases` 把所有非零子进程退出归为 1，零执行数也为 1；`env_error` 可输出日志尾部。
这些是源码观察，不能在引擎化时继承为新契约。提升前需要显式收紧并单独验证，不能声称只是移动文件。

## 3. 方案比较

| 方案（均待评审） | 收益 | 代价／限制 |
|---|---|---|
| A. 模板继续复制完整 harness | 离线独立，改动少，已有使用方式熟悉 | 安全修复继续逐仓迁移；偏离“积木成为引擎能力”的目标 |
| **B. 引擎版本化 helper + 项目薄执行器 + 两阶段 init（推荐）** | 通用行为统一修复，项目保留业务判断；与锁底座边界衔接清晰 | 要建立可信导入、版本契约、Windows 和迁移验收 |
| C. 引擎维护完整栈插件并一键编排 | 首次启动体验最自动化 | 栈版本矩阵和数据库生命周期过重，易替用户做安全决策；本期不选 |

推荐 B：真正重复的是执行机制，不是每个仓库的业务规则。A 作为旧仓库兼容路线保留；不强迫迁移。

## 4. 推荐入口与两阶段锁定（待评审）

拟新增 `storyloop init PATH --scaffold --stack STACK`，可重复 `--stack` 描述混合栈；名称只是提议。
无 `--stack` 时仅对无歧义探测给建议，遇到多栈/未知栈返回待选择清单，不猜主服务。
保留原 `storyloop init PATH --settings FILE` 锁定语义；不静默改变现有调用。

1. **生成阶段**：要求未初始化的 Git 根、有名分支、初始工作树干净。只生成三类草案和一份生成清单；
   不写 baseline/config、不修改 Git exclude、不提交、不运行探测到的命令。成功返回 `SCAFFOLD_CREATED`，
   可以是退出 0，但输出必须写“未初始化、需人工补全”；该成功仅代表生成完成。
2. **人工补全**：选择命令与可写范围，实现必需 hook，审阅规范及敏感信息，按项目要求预热离线依赖、验证执行器，
   将生成物和修改提交进仓库。生成阶段不替用户提交，也不运行 shell 探针。
3. **锁定阶段**：原 init 入口在干净提交上读取 settings；有生成清单时，额外检查配置完整性、helper 钉住版本、
   必需 hook 状态和生成物保护范围。未完成返回 2；不创建一个看似可用的 baseline。
4. **接入验证**：按已有 readiness、skills/survey 和 BASE 流程推进；初始化成功不是所有质量门通过。

拟定产物位于 `acceptance/tools/<stack>_smoke.py`、`acceptance/AGENT_GUIDE.md`、
`acceptance/storyloop-settings.json`，另有受保护 `acceptance/onboarding.json` 记录模板版本、helper API/引擎精确版本、
选择的栈、生成文件摘要和必填项状态。清单不是 settings 字段扩展，不能送给现有 settings 校验器冒充支持。
不放进 `acceptance/changes`、`acceptance/smoke` 或任何可变/测试根；新校验拒绝与这些范围重叠。

默认不覆盖文件：同版本、同输入且生成清单摘要完全相同可无写入返回；有人工修改或冲突则列路径并返回 2，
不自动合并，不提供本期 `--force`。多文件生成先在私有临时目录完整渲染和校验，再安装；失败只清理本次创建且摘要仍匹配的文件，
保留任何并发人工修改并明确报告。写入前复查 HEAD/工作树和目标，检测并发变化即停。

现有 bootstrap 依次写 exclude、config、baseline、收养系统冒烟，再做可选适配器检查，并不是完整原子事务。
**新增要求**：先完成可提前执行的校验，再以独占初始化锁保护控制面写入；失败回滚本次新增控制文件及本次 exclude 变更，
仅当内容仍匹配本次写入时恢复，不能删除预存状态或掩盖并发修改。已有 baseline 一律拒绝此生成入口。
这些是拟修改的行为，不是现状保证；它们是否纳入 T4 必须评审。

## 5. helper、模板与项目责任（待评审）

### 5.1 helper 的最小契约

拟用 `storyloop.testing.smoke_harness.v1` 作为公开命名空间，具体 API 名称在批准后的计划确定。
只包含：安全 case 解析、候选同步、scratch 租约、受控 argv 执行、端口与就绪等待、进程树回收、结构化结果和脱敏错误。
薄执行器负责 build/start/ready/run-case/cleanup 组合，项目专用数据准备是显式 hook；默认不提供执行 SQL 的实现。

| 模板内容 | 默认状态 | 何时可运行 |
|---|---|---|
| 通用骨架及阶段顺序 | 可读取，不伪造成功 | 必填 hook 与配置全部明确 |
| Maven / Node / Python 栈提示 | 显示探测来源、命令候选、离线和分层检查项 | 人确认真实模块和 runner 后 |
| Gradle / 未知栈 | generic 骨架，显式标记未提供特化实现 | 项目补齐；不计入首批开箱成功样本 |
| settings | 合法 JSON 草案，待填项由清单记录；不使用能“成功”的空命令占位 | 引导路径锁定校验拒绝未填项 |
| AGENT_GUIDE | 目录权责、五层测试、case 契约、缺口与参考文件位置 | 人填写仓库约定并审阅提交 |
| 数据准备／鉴权客户端 | 未实现，不含凭证 | 项目单独设计并获必要授权 |

若项目明确不需要某阶段，须在清单记录 `not_applicable` 及理由；否则未实现 hook 抛环境错误并退出 2。
不生成空通过测试、假 system smoke 或“READY”声明；执行器自身冒烟夹具与业务验收分开。

### 5.2 导入与裁判边界

只在项目脚本写普通 `import storyloop` 不足以保证可信性：候选可创建同名包，脚本目录/工作目录或 PYTHONPATH 可能覆盖引擎。
推荐由引擎使用受信安装环境的绝对解释器、隔离启动参数及绝对 launcher 路径启动 helper，
先核验真实安装根与受保护版本记录，再加载受保护薄执行器；候选路径不得参与引擎/helper 模块解析。
项目业务依赖在独立子进程中按项目规则加载；不得通过修改 `sys.path` 把候选插到裁判前面。
新增 launcher 只是执行协议的适配，不让项目代码提供 PASS 判定逻辑；最终 verdict 仍由引擎按退出码和证据决定。

生成的调用 argv 应由安装环境生成，不把开发机绝对路径提交成可移植模板。解析受信 launcher/解释器的规则由引擎持有，
路径和版本在执行记录可审计；离线手动/CI 运行需先安装同版本引擎并显式解析，缺失时 2，不回退 vendored 或网络安装。
新版 manifest 调用形式与现有 `{python}` 路径脚本如何并存是 Q3 的批准事项，不在本文假称已有参数。

### 5.3 版本、升级与旧仓库

生成清单钉住精确引擎发布版本和 helper API 主版本，发布包包含模板资源；实际执行校验一致性。
同 API 主版本仍不静默升级：安全修复及行为变更需可审阅 diff、执行器 self-test、旧 case 回归，
再通过 `base-propose → 独立提交 → base-update` 更新保护清单/薄执行器；不支持版本返回 2，保留原可用环境便于回退。
跨主版本显式迁移，不自动重写项目 hook。版本元数据必须受底座保护，不能仅信可编辑控制面配置。

现有 vendored harness、旧 manifest 和 init 用法继续工作；不删除 examples，不要求已有仓库获得新清单。
迁移先生成仓库外草案供比较，再按 BASE 路径纳入；不直接在已锁底座上重新 scaffold，不删除 `.storyloop` 绕过升级。
迁移增加的新保护路径若落在既有可变区内，必须先解决边界冲突；本期不能自动放宽底座规则。

## 6. 错误、安全与平台边界（待评审）

| 边界 | 新契约 |
|---|---|
| case 范围 | 只运行 manifest 传入的文件；拒绝空列表、重复／越界／缺失／不支持的 case，禁止全目录发现及附加 `acceptance/ui` |
| 结果 0/1/2 | 0：确实执行且全部通过；1：已运行用例的行为断言失败；2：未配置、0 用例、依赖缺失、导入/启动/构建/超时/清理失败及不明结果。混合结果以 2 优先，RED 只能接受 1 |
| runner 证据 | 不把子进程任意非零都映成 1；分别收集执行数、断言失败与环境错误，未识别的 runner/错误格式视为 2，不能猜测 |
| argv | 仅数组，`shell=False`，无 eval/字符串拼 shell；占位逐参数替换；拒绝 shell wrapper 绕过现有原生执行器约束 |
| 路径 | 复用 [path_security.py](../../../storyloop/path_security.py) 规则；拒绝绝对/`..`/盘符逃逸及 symlink/hardlink/reparse；写入目标与读取 case 均验证 |
| scratch | 按仓库身份与 run 独占分配；记录归属与租约，不按用户栈名共用目录。同步基于内容而非仅 mtime；删除只限本租约镜像中源已删除文件 |
| 缓存 | 单独声明可复用依赖缓存，不能把旧源码/测试混成缓存；并发不共用可写构建目录；配置缺失返回 2 |
| 清理 | finally 回收本次进程树和资源；只删除本次拥有的目录/对象，路径校验失败时不执行递归删除；清理失败报告 2 并列无敏感信息的人工处置线索 |
| 环境 | 保持 smoke_runner 的 PATH、SYSTEMROOT、TEMP、TMP 及引擎设置的 PYTHONDONTWRITEBYTECODE；不自动传 HOME、凭证或 PYTHONPATH，不因某栈难跑而放宽 |
| 离线预热 | 用户在接入前完成依赖和浏览器预热；明确缓存寻址，缺失返回 2。生成器/执行器不下载、不装包、不偷偷切在线模式 |
| 就绪 | 默认不把 HTTP 4xx/5xx 当健康；项目声明只读探针及预期状态；端口抢占和超时归环境错误，不自动修改应用 profile |
| 日志 | 记录阶段、退出码、脱敏摘要；不复制配置原文或默认打印日志尾部；异常不得泄露凭证和连接串 |
| Windows | 使用平台进程树能力而非照搬 killpg；原生解释器 argv，空格/Unicode 路径，盘符、大小写和 reparse 均验证；`.cmd/.bat/.ps1` 不被生成器自动放行 |

引擎控制判定权遵守 [ADR 0001](../../decisions/0001-external-loop-owns-verdict.md)；
受保护产物升级遵守 [ADR 0004](../../decisions/0004-foundation-vs-mutable-area.md)；
case 选择遵守 [ADR 0008](../../decisions/0008-smoke-core-flow-only.md)。
[ADR 0014](../../decisions/0014-skills-as-packaged-modules.md) 的随引擎发布、版本化思路可复用，
但其中“项目副本优先”的技能文本规则不能用于执行型 helper，否则项目能覆盖裁判代码。

|---|---|

| 不假绿 | 空/漏填 hook、零测试、启动失败、依赖缺失均为 2；已执行断言失败为 1；有效用例通过为 0；混合错误优先 2 |
| case 精确性 | 传 A 只运行 A；放置会失败的 B/UI 资产也不触发；非法路径在启动服务前拒绝 |
| 可信导入 | 候选放同名 storyloop 包、伪 helper、修改 sys.path/PYTHONPATH 时不能覆盖引擎；版本不匹配 2；业务子进程不能成为裁判来源 |
| scratch | 两仓同栈、同仓并发隔离；同大小/mtime 的内容变化被同步；删除只作用于本次镜像；缓存缺失和清理失败可解释 |
| 离线与安全 | 禁网下预热夹具可跑，未预热返回 2；白名单不变；生成物/日志不含测试登录值、连接串；没有隐式数据库或 schema 操作 |
| Windows | 原生 Windows 上执行路径、进程树回收、wrapper 拒绝和 reparse 反例；WSL2 结果不替代 Windows 证据 |
| 兼容迁移 | 既有 vendored 夹具保持原行为；新 helper 迁移经 BASE，旧版本可恢复；旧 CLI 和 manifest 不被静默重写 |

### 7.1 半天目标的测量方法

建议将半天定义为 **4 小时人工有效工时**。起点：仓库可用、依赖预热完成且测试环境权限已明确；
终点：生成物补全提交、干净 init、执行器 self-test 的 0/1/2 均验证、readiness 结果及所有缺口经人审阅。
ready 失败不得当作成功；人工确认的允许缺口必须单列，不能与完整 READY 混为一类。

分别记录机器等待、下载预热、审批等待、人工配置、排错与后续首次业务闭环工时；
下载、上游已有构建故障、全新数据库隔离设计、首次真实产品变更不算在 4 小时内，但必须报告其实际耗时或未完成，不能隐去总成本。
至少选择一个全新独立仓库和一个 RuoYi 同类混合栈重建样本，按相同条件记录模板前后工作项；
RuoYi 熟悉度有学习偏差，只作为复现样本。小样本只能说明该栈该环境结果，不能宣称普遍从两天降至半天。
真实模型调用、模拟适配器、本机 full/core、远程 CI 分列记录，未执行写未执行；不为凑通过重复真实调用。

## 8. 待决问题

以下推荐均未获批准，答案需在评审后回写；本轮到此停下，不产出实施计划。

| 问题 | 推荐 | 备选及代价 |
|---|---|---|
| Q1：init 是否两阶段？ | 同入口显式 `--scaffold` 生成，提交后原 init 锁定 | 独立 `scaffold` 子命令更易理解但偏离用户期望入口；一键提交锁定不推荐，隐藏审批 |
| Q2：首批模板覆盖？ | Maven、Node、Python 及 Maven+Node 组合；Gradle/其他仅 generic | 全部栈同时特化会扩大平台矩阵；仅 RuoYi 缩小验证面但收益不够通用 |
| Q3：helper 如何调用和版本钉住？ | 引擎受信 launcher、隔离导入、精确版本 + API 主版本，明确新增 manifest 调用契约 | 直接 import 简单但有遮蔽风险；完整 vendoring 继续重复升级。涉及接口变化需明确批准 |
| Q4：init 失败回滚是否并入本期？ | 纳入最小控制面事务与故障注入，避免新入口扩大半初始化风险 | 独立前置任务可减轻 T4，但锁定流程验收需等其完成 |
| Q5：数据与登录模板深度？ | 仅阶段契约和待填项，不写 SQL/鉴权实现或运行档 | RuoYi 专用插件会快些，但引入安全配置及数据库授权范围，本期不推荐 |
| Q6：半天测量及完成口径？ | 采用 §7.1 的 4 小时人工工时，另报总耗时、前置条件和 readiness 缺口 | 计全部日历时间更贴用户体验，但依赖下载/审批波动大，需要更广样本 |
| Q7：scratch 与缓存策略？ | 每 run 独占构建目录，依赖缓存显式复用 | 持久共享构建目录更快，但并发污染与删除归属更复杂 |
