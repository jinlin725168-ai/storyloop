# 敏感输出处理：共享脱敏与诊断边界

- 状态：待评审；本次只设计，不改代码。
- 依据：`origin/main` `4692acb` 的调用路径；PR #49 第三轮审查第 1–3、5 条。审查实测 `redact('s3://' + 'a:'*100000)` 约 27.8 秒；这是问题证据，不是本设计重新测得的结果。

## 1. 保护目标与当前写出位置

要保护的是子进程、代理回复、人填理由及异常文本里可能出现的凭证。读者包括操作者、CI 日志读者、报告接收者，以及能读项目内 `.storyloop` 文件的人；这些范围不能假定都等同于本机操作者。引擎需要保留退出码、状态、测试计数、错误类型、少量上下文和可定位的诊断路径，不需要在可分享输出中保留整段原文。脱敏不能被当成隔离或保证发现所有秘密的措施。

按 `redact()` 的直接调用方盘点；同一模块的多次调用均列在同一行。表中的“原文”指未经处理的输入，现有其他未调用 `redact()` 的输出另在实施时审计。

| 调用方 | 目前写出或展示位置 | 需要原文吗 |
|---|---|---|
| `call_log.py`：`open_call`、`close_call`、`record_context`、`record_lesson_evidence` 经 `_redacted`，以及 `response.txt`、`stderr.log`、`meta.error` | `.storyloop/state/telemetry/calls/<call-id>/`；`request.json`、`response.json`、`response.txt`、`stderr.log`、`meta.json` 是本地持久记录。`meta` 的白名单字段还会进入报告展示 | 可分享记录只需结构化概要、截断片段和诊断文件路径；解析失败时原始回复、stderr 仅供本机排错，且需要单独授权保存 |
| `agent_transport.py:_check_process` | stderr 尾部进入 `StoryLoopError`，随后可能进入停点、状态、CLI | 不需要完整原文；退出码、失败类别、有限尾部和诊断路径足够 |
| `project_loop.py`：`WORKSPACE_TAINTED`、`agent_failures.message`、`stop.error` | `pause`/`save_run` 写 `.storyloop/state/runs/<id>.json`，并返回停点给 CLI；`agent_failures.message` 另被报告证据读取 | 不需要原文；保留代码、短摘要、路径 |
| `cli.py`：`_error_stop`、异常 `message`、`_redact_value` | CLI stderr JSON；`--json` 的正常结果由 `cli_output.display` 输出，停点也可出现在 stdout | 不需要原文；提示必须可读且有诊断路径。正常结果的任意嵌套字符串不能只靠错误分支保护 |
| `report_evidence.py:_bounded` | 读取运行状态、调用 `meta` 等，形成报告展示快照；`report_presentation` 将其冻结到报告 | 不需要原文；该处虽先限制每个字符串到 20,000 字符，仍应只接受源头安全字段 |
| `smoke_runner.py:_run_test` 的 stdout/stderr 两处 | 结果对象，随后写 `.storyloop/evidence/<id>/` 的 RED/结果 JSON，并可进入 CI、报告 | 不需要完整原文；状态和计数必须来自未删减的执行结果，公开证据只留有界片段与本地诊断路径。目前是先脱敏全量输出、再各截到 100,000 字符 |
| `readiness.py:approve_readiness` | 人填理由进入 `.storyloop/state/readiness.json`，并可被 CLI 展示 | 不需要超长原文；保留有界、可审核的理由，拒绝或提示操作者避免放凭证 |
| `testing/mock_adapter.py:_safe` 与两处 stderr | 测试脚本旁的 `requests/*.json` 和测试进程 stderr | 测试夹具不需要原文；与生产边界共用规则，避免测试辅助程序成为泄漏入口 |

另外，`agent_transport` 在调用期间把原始 stdout/stderr 放进 `trace`，`run_process` 在内存与临时文件中处理进程输出；这些是从进程到上述写出点的上游。`call_log` 说明明确称调用记录“用于诊断，不是证据”，但目录仍持久化、可被复制，不能据此视为安全存储。`cli_output.display` 对正常 `--json` 结果直接序列化，实施时要审计所有进入该出口的字段，而不只审计直接调用 `redact()` 的分支。

## 2. 方案比较与决定建议

| 方案 | 优点 | 主要缺口 |
|---|---|---|
| A. 保留正则黑名单，补 URL 线性扫描、JSON/dict 键、复合变量名、`github_pat_`/`gho_`/`ghs_`/`AKIA` 等 | 改动小，旧文本形态延续 | 代理输出与第三方凭证形态无穷；新规则易误抹路径、SHA、普通诊断。即使消除已知 ReDoS，也不能承诺不泄漏 |
| B. 源头不记录原文；可分享位置只放结构化摘要，原文仅在有明确诊断需要时写权限受限的本地文件，输出给路径 | 最直接缩小泄漏面；不依赖猜测秘密形态 | 需要逐个迁移调用方、定义本地诊断权限和清理；片段减少会影响排错习惯 |
| C. 混合：源头字段 allowlist + 有限高置信度形态处理 + 输入上限、线性时间扫描 | 兼顾稳定的机器字段、有限诊断上下文和实际排错 | 仍不能识别任意新凭证；必须把“不保证全覆盖”写进接口与文档 |

**推荐 C，以 B 为默认边界。** 可分享/持久证据只记录明确定义的状态、计数、错误码、有限诊断片段与诊断路径；不默认保存任意原始子进程输出。原文只在操作者显式开启本地诊断时保存，目录 0700、文件 0600、排除 Git、限制总量和保留期，禁止跟随符号链接；CLI 只显示相对项目的诊断路径，不自动上传、复制到报告或 CI 工件。无诊断授权时直接丢弃原文。即使本地文件受限，也不能防御同用户恶意进程或操作者主动分享。

`redact(value: str) -> str` 保留为纯文本兼容入口，改成有界、线性时间的高置信度扫描：仅识别明确的 `Bearer`/Basic 头、键值语法中完整的敏感键（含 JSON/dict 引号、`SECRET_KEY`、`TOKEN_VALUE` 等复合名）、已知密钥前缀及 URL userinfo；其余交给源头字段 allowlist。规则必须有词法边界，空白不得跨行吞掉下一条诊断，不凭“token/secret 附近有长字符串”判密。凭证样本仅用合成值。对于不确定的自由文本，显示固定省略标记和诊断路径，不能宣称扫描后一定安全。

## 3. 性能与截断契约

- 脱敏扫描最坏时间和额外内存均为 O(n)；不得使用会在长无匹配输入上重复回溯的嵌套量词。URL userinfo 可用单次状态扫描或经证明线性的有限规则。已知反例 `s3://` 后重复 `a:` 以及长单行 JSON 必须在线性测试中覆盖。
- 任何展示或持久化调用方先按**字节**上限选取前缀/尾部，再脱敏；若采用流式处理则按固定块处理并携带有限的边界状态。截断不能留下半个秘密：切口处未完结的键值或 userinfo 整段替换成 `[REDACTED]`/`[TRUNCATED]`。状态判定和测试计数可用完整流式输入，但不把完整流交给脱敏器。
- 建议上限：CLI 错误 4 KiB、停点与报告片段 8 KiB、每路子进程诊断 64 KiB、一次调用记录总计 256 KiB；超过上限标 `truncated`，保留原有状态/计数。具体旧字段长度以兼容测试锁定后调整。
- 可测目标：在项目 Linux CI 标准 runner 上，10 MiB 合成输入的 `redact()` 单次耗时 <1 秒；200 KiB 冒号链和 1 MiB 单行 JSON 不得出现超线性增长。日常测试还用 2 倍长度的时间比约束回归；绝对耗时另在固定 runner 上测，避免不同机器的短时抖动误报。调用方必须在传入 `redact()` 前就执行上限，不能靠函数返回后再截断。

## 4. 兼容与迁移

已有报告和证据中的 `status`、`returncode`、`counts`、`evidence_sha256` 与判定来源不变；不回写历史文件。新结果优先保留 `stdout`/`stderr` 等旧键，值改为有界安全摘要，增添可选的 `truncated` 与 `diagnostic_path`；若受保护证据的格式/摘要规则不容新增键，先通过现有版本化迁移机制设计新版本，不能静默改验收判据。报告只引用安全摘要，调用记录的 `response.txt`/`stderr.log` 不再承诺含完整文本；需要原文的排错流程改为显式本地诊断。

CI 保留测试名、失败状态、计数、退出码和少量安全上下文；大段输出改为“已截断/本地诊断路径”，CI 不能依赖本机路径可访问。若操作者未开启本地诊断，提示原文未保存。迁移前要核对快照、`storyloop log/report/ci --json` 消费者和现有解析器；格式变化需文档、版本及兼容测试同步，不把脱敏后的文本用于原有判定。

## 5. 测试与实施拆分（待批准后执行）

每项按 TDD：先新增失败断言，确认在旧实现上失败，再实现，再跑通过。测试只用合成凭证。

| 任务 | 先红的测试与通过条件 | 归属 |
|---|---|---|
| 1. 固定输出边界与旧格式 | 表驱动列出每个调用方的字段、去向、最大长度、是否持久化；确认旧 `stdout`/`stderr`、状态和计数基线 | FAST |
| 2. 线性文本扫描 | 正例：JSON/dict `Authorization`、`token`、`password`，复合键名，已知前缀、URL userinfo；反例：普通路径、40 位 SHA、模块名、跨行文本。旧实现先红；再做无回溯扫描 | FAST；长串与大输入属 SAFETY |
| 3. 源头有界输出与本地诊断 | `call_log`、代理失败、停点、报告、冒烟、CLI、readiness、mock adapter 各注入合成凭证及超长输出，断言可分享字段不含原文、诊断路径和权限/清理正确；冒烟先截断再扫描，状态与计数不变 | SAFETY；纯投影函数可放 FAST |
| 4. 兼容与性能门禁 | 现有报告/日志快照、CI 失败可读性、JSON 消费者；20/200 KiB 冒号链、1/2 MiB JSON 的增长比，固定 runner 测 10 MiB <1 秒；回归检查不得产生新泄漏或误抹 | FAST 快照；SAFETY 集成与性能 |

本设计不批准实现，也不改变现有引擎判定行为；人评审后再写逐步实施计划。
