## 1. 目标与边界

内环执行规则，外环修改规则，外环的决策者是人（原则 10）。现在每个变更都留下了报告、运行状态、调用账本，但没人把它们放在一起看：`max_attempts` 是否合适、轻档是否放过了问题、钱花在哪个角色上，都只能凭印象判断。本期提供一个只读命令，把这些记录汇总成指标表，按规则给出调整建议，并附上证据（具体是哪些变更），由人决定改不改。

本期交付：

1. `storyloop metrics PATH [--since 日期] [--json] [--save]`；
2. §11 表中的 12 组指标，口径固定、可复算；
3. 调整建议：规则表 + 阈值 + 最小样本量，每条建议列出触发它的变更 ID；
4. 延后项的可计算触发信号（总体设计 §13 延后项表中能从记录算出的几项）；
5. `storyloop ci --record`：把 CI 结果写成一个文件，供"本地绿、CI 红"使用。

不做：

- **不自动改规则**：建议只输出，不写配置、不开草案（Q5）；
- 不做跨仓库汇总（延后项"跨仓库的经验晋升"的触发信号是同一技术栈有两个以上仓库，目前没有）；
- 不做趋势图、看板：输出是 Markdown 表和 JSON，需要图时由人拿 JSON 自己画；
- 不回头补算历史上没有记录的字段：缺数据的指标显示"无数据"及原因，不估算。

## 2. 数据来源

| 来源 | 位置 | 持久性 | 主要内容 |
|---|---|---|---|
| 报告快照 | `reports/storyloop/<ID>/report.json`（已提交） | 随 Git 永久保存 | `status`、`routing`（`initial`/`effective`/`history`）、`correction`（`failures`/`overrules`/`supersedes`）、`telemetry`（`calls`/`attempts`/`cost_usd`/`by_role`）、`review`、`layers` |
| 运行状态 | `.storyloop/state/runs/<ID>.json` | 本机，不在 Git 里 | 没有报告的变更（停住、作废）；`agent_failures`、`answers`、`resets`、`repairs`、`stop`、`manual_acceptance` |
| 变更记录 | `.storyloop/state/changes/<ID>.json`、`openspec/changes/<ID>/` | 部分在 Git | `nature`、fix 的 `origin_change`、批准时间 |
| 调用账本 | `telemetry.ledger_entries` | 本机 | 按调用的角色、档次、模型、耗时、费用、经验字段（子项目 5） |
| CI 结果 | `--ci-results DIR` 下的 `ci-*.json`（Q2） | 由人从 CI 下载 | 每次 `ci --record` 的结果 |

**取数优先级（Q1）**：有报告快照的变更以快照为准，运行状态只补快照里没有的字段；没有快照的变更只用运行状态。同一字段两处不一致时以快照为准，并在 JSON 输出的 `discrepancies` 里列出。

**变更集合**：`--since` 按变更的批准时间过滤（没有批准时间的按运行开始时间）；默认全部。被 supersede 的变更计入集合，但"首轮通过率"等以终态为分母的指标只算终态为 `PASSED` 的。

## 4. 调整建议

建议由固定规则产生，规则和阈值都写在代码里的一张表中，阈值可在 `.storyloop/config.json` 的 `metrics.thresholds` 覆盖（Q4）。每条规则有最小样本量，样本不够时不出建议，只写"样本不足（n/最小值）"。

| 规则 | 条件（默认值） | 最小样本 | 建议文字（要点） |
|---|---|---|---|
| R1 | 预算用尽的变更占比 > 20%，且其中多数最后一轮的失败特征与前一轮不同（仍在进展） | 10 | 考虑提高 `max_attempts` |
| R2 | 首轮通过率 < 40%，且 M3 失败归属中 `implement` 占比 > 60% | 10 | 实现阶段问题集中：先看判据和合同是否写清，再考虑默认档次 |
| R3 | 运行中升档比例 > 20%（按初始档位） | 10 | 该档位的 L1 规则经常低估，列出升档原因中出现最多的规则 ID |
| R4 | 规格返工率 > 15% | 10 | 合同模板或澄清不足，列出返工变更 |
| R5 | `agent_failures` 平均每变更 > 0.5，或某适配器占比 > 70% | 5 | 适配器稳定性问题，列出适配器 |
| R6 | 轻档缺陷逃逸率 > 10% | 10 | 收紧轻档门槛 |
| R7 | 本地绿 CI 红 > 5% | 10 | 本地判据偏弱，列出 CI 失败的层 |
| R8 | 强行继续的超重变更中，失败或作废 > 50% → 拆分阈值合理，建议遵循；< 20% → 阈值可能过严 | 5 | 二者择一 |
| R9 | 审查发现被驳回比例 > 30% | 10 | `review_thresholds` 可能过严 |
| R10 | 轻档变更的 M9 中位数 > 1.5 | 10 | 轻档流程偏重 |
| R11 | 某角色的已知费用占比 > 50% | 5 | 列出该角色的档次，提示检查默认档次（不建议具体模型） |
| R12 | 经验提供后复发率 > 30%，或提供后未声称使用的比例 > 70% | 10 | 前者：建议把相关条目升级为检查；后者：取用可能过宽 |

M10 不产生建议，只排出介入最多的三种，写"自动化方向参考"。

建议输出格式：规则 ID、触发值与阈值、样本量、证据变更 ID（最多 10 个，多出写数量）、建议文字、"由人决定"。不输出"应当改成多少"的具体数值，只给方向（Q3）。

## 5. 延后项信号

总体设计 §13 延后项表中能从记录算出的，与指标一起输出，只报"是否出现触发信号"和证据：

| 延后项 | 可计算的信号 |
|---|---|
| 变更链执行语义 | supersede 链长度 > 2 |
| 故事级检查点 | 多故事变更中，因后面故事失败而整轮重来的变更数（`failures[]` 里失败用例集中在最后一个故事的轮次） |
| 顺利完成的变更也沉淀系统冒烟 | 系统冒烟用例数在最近 10 个 `PASSED` 变更里没有增长 |
| 非确定性判据重复执行 | 同一变更里同一验收用例先绿后红或先红后绿而实现未改（相邻两轮实现提交相同） |

其余延后项（升级性质、Spring 仓库、安全模块、协作出口、perf/docs/port、知识库补充、跨仓库晋升）的信号来自外部事件，本期不计算，在输出里列为"需人工判断"。

## 6. CI 结果记录

- `storyloop ci PROJECT --change ID --record FILE`：在原有输出之外，把 `{"version": 1, "change_id", "status", "commit": <HEAD>, "recorded_at", "layers": {acceptance, smoke 的 status}}` 写到 `FILE`。`FILE` 在项目目录之外或 CI 工作区内，由项目 CI 作为构建产物上传。
- `metrics --ci-results DIR`：读 `DIR` 下所有 `ci-*.json`；同一变更多次结果取 `recorded_at` 最新的一次；`commit` 不是该变更的合并提交或其后代的结果忽略并列入 `missing`。
- 没给 `--ci-results` 时 M6 为 `null`，原因 `CI_RESULTS_NOT_PROVIDED`。

## 7. 命令与输出

```
storyloop metrics PROJECT [--since YYYY-MM-DD] [--ci-results DIR] [--json] [--save]
```

- 默认输出中文 Markdown：一张指标表（指标、值、样本、说明）、建议列表、延后项信号、缺数据汇总。
- `--json`：完整结构（每项指标的分子、分母、变更 ID、缺失原因；建议；信号；`discrepancies`）。
- `--save`：同时写 `reports/storyloop/metrics/<YYYY-MM-DD>.md` 与 `.json`，不自动提交（Q6）；同一天重复执行覆盖。
- 只读：除 `--save` 写的两个文件外不改任何文件、不调用代理、不需要工作区干净。

Task 1 相对原设计的校正：当前 stop 对象没有 `code`，实际停点键是 `stop.status`；answers 与人工验收各有独立状态文件；报告保存批准日期，但不在顶层保存 `source_head` 或 `contract_commit`。`agent_failures` 没有 adapter 字段，收集器不从角色推断。旧记录没有保存的 smoke、故事或逐次结果保持缺失，明确空列表仍保留为空列表。未知报告版本跳过并记录 `UNKNOWN_REPORT_VERSION`。所有读取逐文件受根路径、符号链接和大小上限约束；账本 helper 不绕过前置校验。cohort 的三个直接来源完整流式枚举，不设静默样本数上限。

### Task 2 指标口径校正

| 项 | 实现口径 | 原因 |
|---|---|---|
| M1b 样本 | `denominator`/`n` 是已记录 `attempts` 的均值样本；`budget_denominator` 是 R1 使用的完整 cohort | 缺失尝试数不能当 0，同时预算用尽比例不能因均值字段缺失而缩小分母 |
| M1b 进展 | `progressing_denominator` 只包含最后两轮均有非空 `signature` 的预算用尽变更 | 无特征记录时不猜测为“未进展” |
| M4 adapter | `agent_failures[].adapter` 缺失时归到“未记录” | 当前实际 schema 不保存 adapter，不从 `role` 推断 |
| M5 证据 | `changes` 只列被 fix 的 `origin_change` 指向的已通过变更 | 规则建议需要逃逸证据 ID，不是全部分母 ID |
| M7 outcome | 成功是 `PASSED`；失败是实际运行持久化的 `BUDGET_EXHAUSTED`、`NO_PROGRESS`（并兼容旧 `FAILED`）；作废是 `SUPERSEDED`；其他状态以 `NO_SAMPLE` 记入 `missing` | R8 需要统计强行继续后实际的失败停点；`SPLIT_RECOMMENDED`、设计审批和 `IMPLEMENTING` 等尚未得出 outcome，不进分母 |
| M8 分母 | 当前审查停点 finding 数加上各 `overrules[].findings` 保存的历史 finding ID 数 | 最终报告的 review 已不再保留被驳回 finding 为停点目标 |
| M9 Git 证据 | 要求 `source_head → contract_commit → implementation_commit` 祖先关系；空实现 diff、二进制 `numstat`、缺失或不可达提交都记 `UNREADABLE` | 这些情况无法产生可复算的文本行数比，不能伪造为 0 |
| 模块拆分 | 通用构造与解析 helper 放在 `metrics_compute_support.py` | 为 Task 3 继续扩展 `metrics_compute.py` 预留空间，两个文件均保持在 500 行内 |

### Task 4 规则与延后项信号校正

| 项 | 实现口径 | 原因 |
|---|---|---|
| R1 样本与进展 | 预算用尽比例使用 M1b `budget_denominator`（旧夹具回退 `n`）；“仍在进展”只读 `progressing_value` 或其真实分子、分母，无记录时返回 `PROGRESS_EVIDENCE_NOT_RECORDED` | 平均尝试轮数的样本不是预算用尽比例的完整 cohort，缺失的失败特征不能猜成“没有进展” |
| R3 升档原因 | M2 按初始档位保留实际向上升档记录中 `reason[].rule_id` 的计数；R3 输出最高频规则 ID，平票按 ID 排序 | 原始 `routing_history` 已持久化真实原因，应在指标聚合时保留而不是在建议层重读或猜测 |
| R5 适配器集中 | “未记录”保留在总失败数中，但不作为一个真实适配器；已知适配器相对全部失败的占比足以触发时可确定触发，否则只要仍有未知归属就显式返回不可用 | 部分未知证据不能被静默用于阴性结论，已知计数相对全体的占比则是可证明的下界 |
| R7 失败层 | R7 按失败次数降序、层名升序输出 M6 `by` 中的真实失败层；没有有效正计数时返回 `CI_LAYER_EVIDENCE_NOT_RECORDED` | M6 已保留失败层计数，建议应携带解释其触发值的证据维度，空或无效维度不能产生无解释建议 |
| R8 失败证据 | 高分支使用 M7 `failure_changes`；低分支使用整个实际 outcome cohort 的 `changes` | 高分支由失败变更支撑，低分支由低失败率的完整分母支撑，零失败时也必须有证据 |
| R11 样本 | M11 顶层和分组公开整数 `known_cost_calls`；R11 直接以顶层精确计数判断最小样本，仅为小型旧夹具保留可验证的 coverage 回退 | 四位小数覆盖率不可逆，大 cohort 不能通过 `calls × cost_coverage` 精确恢复实际有费用回报的调用数 |
| R12 子指标 | 复发率与未声称使用率分别按各自 `n`、`changes` 和阈值评估，建议附 `metric` 标识 | 两个子指标的分母和证据不同，不能合并成一个样本 |
| 延后项历史证据 | 变更链使用实际 supersede 链；系统冒烟只在最近十个通过变更都有真实结果列表时判断；故事重跑和非确定性判据返回 `HISTORICAL_EVIDENCE_NOT_RECORDED` | 当前 collector 只透传最终 stories、layers、traceability，没有逐轮实现提交、逐用例结果或故事失败历史 |
