## 来源与限制

🔧 表示命令、Git、摘要或引擎确定性计算；👤 表示审批、回答和人工验收记录；🤖 表示代理陈述，并区分代码推断与 AI 样本。`AVAILABLE`、`NOT_AVAILABLE`、`PENDING` 独立表达可用性，未知不会显示成零、空集合或通过。

对账以已持久化的实际 call ledger 为清单，不能证明没有落盘的理论调度阶段；诊断 metadata 不是验收裁决证据。外部 CI 没有权威记录，完整事件/事实演变历史未持久化，文件路径重叠不能证明语义覆盖，运行时并发与会过期常量没有专门分析来源，记忆模块尚未实现。这些项目在报告中保持 `NOT_AVAILABLE` 或明确 limitation。

## 实施裁决与代价

| 裁决 | 原因 | 代价或限制 |
|---|---|---|
| 按“继续设计，继续实施”直接执行，并逐任务独立审查 | 用户已授权本次工作，不重复设置批准门 | 如范围理解错误，需要撤回独立特性分支的相应更改 |
| 顶层 version 保持 1，新增 presentation.version=1，旧报告保留原渲染器 | 历史回执需要字节兼容 | 维护两条渲染路径 |
| 无可信来源的 CI、记忆、历史、语义覆盖和理论调度次数明确未知 | 不伪造缺失证据 | 本模块不替代后续模块或完整事件记录系统 |
| 对账不新增验收授权门，但不一致必须明确显示 | 诊断日志不是可信裁决证据 | 放行仍需结合报告中的证据缺口判断 |
| 生成报告前保存当前运行状态，保持 phase/status 不变 | 最后一轮实现和审查事实此前可能仅存在内存 | 增加一次状态写入，并由恢复回归检查 |
| 不根据文字猜测 AI 样本来源；来源缺失明确标注 | 现有 schema 没有权威样本来源字段 | 历史样本无法自动细分，需将来持久化来源协议 |
| 技能断言按实际角色映射；无技能角色明确为 [] | 不能为了“每次非空”的测试要求伪造技能使用 | 角色映射变化时须同步测试预期 |
| 区分实际执行记录与项目根目录中的命令重放 | 原验收候选目录会被删除，不能将其路径冒充可复制命令 | 重放面向当前项目副本；绝对候选路径需安全映射，无法映射时明确不可重放 |
| 历史覆盖未知不屏蔽已落盘的孤儿、重复或未结束调用 | 这些异常已有实际记录，不需要推测理论调度次数 | 旧账本混有真实异常时会显示不一致；完全无记录时仍是未知 |
| 验收结果增加实际 cwd 元数据，保留原 argv，并显式映射完整候选根路径 | 同时满足真实执行追溯与命令重放 | 嵌入其他参数文本的候选路径不做猜测替换，保持不可重放；不新增验收授权门 |
| Git 输出通过管道限字节并限制整个快照时间，禁用外部 diff/textconv | 避免先无限读取再截断，也避免执行仓库自定义比较器 | 大型、慢速或无法解码的快照可能不完整，报告必须显示限制 |
