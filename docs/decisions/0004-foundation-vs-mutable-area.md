# 0004 底座与可变区分离，底座只通过 BASE 迭代演进

日期：2026-09-17（可变区可为任意目录的放宽在同日决定）

## 问题

功能代理顺手改 pom、改配置、改工程入口，几次之后没人知道底座是什么样了。

## 决定

`init` 锁定已跟踪文件指纹为底座；`module_roots` 是可变区，可以是任何目录，包括已有代码目录。功能变更触碰底座或集成点即停在 `BASE_CHANGE_REQUIRED` 生成提案；计划中的底座改动直接 `base-propose`。BASE 迭代在原分支独立提交，`base-update` 校验路径一致、回归通过后底座版本加一。

## 理由

- 品牌替换、页面调整这类需求也会改已有目录，所以可变区不能只限定 `modules/`。
- 底座改动要有人审、有完整回归、有版本号，和功能改动混在一起做不到。

## 代价

- 接入时要认真决定可变区和 `integration_paths`，漏了会频繁撞边界。
- 功能变更遇到 BASE 需求时会停一次。
