# 0002 验收用例在实现前盲写，与合同一起提交，先证明 RED

日期：2026-09-16

## 问题

测试在实现之后写，就会迁就实现；测试和实现由同一个代理写，就会互相配合。

## 决定

批准后，冒烟角色只看合同盲写 `acceptance/smoke/<id>/`，引擎把它和合同一起提交并保护字节；在隔离候选副本里跑一次，只有行为断言失败才算有效 RED；没有 RED 不调用实现代理。实现代理永远不能改这个目录。

## 理由

- 验收级红灯证明用例真的在测缺失的功能，而不是在测已有行为。
- 环境错误不算红灯，否则"跑不起来"会被当成"功能缺失"。

## 与实现级"先红后绿"的区别

这条决定说的是**验收级**的 RED：引擎在实现之前对冒烟套件观察到的失败。它不是实现代理内部的 TDD。实现级的先红后绿（先写会失败的单元测试，再写代码让它通过，再重构）发生在 implement 角色内部，由提示词规范并记录在 design.md 的 Tests First 一节，引擎不观察也不证明（见 [0012](0012-implementation-tdd-by-prompt.md)）。两者不能互相替代：验收级红灯保证做的是合同里的事，实现级红绿保证代码是被测试驱动出来的。

## 代价

- 盲写的用例可能有缺陷（定位器、时序），需要单独的修复通道（见 0009）。
- 需要真实可运行的应用，因此冒烟执行器必须能离线构建和启动。
