# 0008 冒烟只含核心链路，UI 回归资产不进冒烟、不是证据

日期：2026-09-21

## 问题

第一版把 `acceptance/ui/**` 下所有历史回归用例附加进每次冒烟。一次变更的第一轮尝试因此失败了 6 个用例，其中 5 个是冒烟用例自身的缺陷、1 个是过时的回归资产，没有一个是实现问题。

## 决定

- 冒烟 = 本次变更的核心链路验收 + 不该坏的基础功能。验收条件以接口可观察行为为主，浏览器用例只覆盖核心链路（每个故事不超过 3 条）。
- Playwright Test Agents 生成的用例第一次执行必然通过，不能作为验收证据；它们是回归资产和页面活文档，放在 `acceptance/ui/<capability>/`，不进候选副本、不是任何门。
- 冒烟角色盲写时复用其中的页面事实（定位器、文案、流程）。

## 理由

- 门越重，误报越多，人对红灯的信任越低。
- 上一轮迭代的 UI 细节变化是正常演进，不该阻断这一轮。

## 代价

- 历史功能的回归要靠项目自己安排（按需跑 `acceptance/ui/`）。
