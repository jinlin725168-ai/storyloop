# 0018 底座变更只由人实现

日期：2026-10-29

## 问题

架构收敛设计 §4.2 曾要求 base 默认由代理实现、强制跨厂商审查（单代理时由人替代），并要求改动判据路径时先在注入的违规上证明新判据跑红。E2a 代理通道虽以预览合入并完成一次真实试用，但八轮以上审查仍未收敛；E2b 尚未交付。需要决定阶段 E 是否继续沿代理实现路线。

## 决定

- base 变更只由人实现，沿用 E1 人工通道。取消 §4.2 中“base 默认由代理实现”“强制跨厂商审查及单代理人工替代”“判据路径被改时新判据先在注入的违规上跑红”三条要求。E1 的具名独立人审和最终人工验收照旧必经。
- base 变更若改动判据路径（系统冒烟清单或判据文件、声明的测试根），候选必须保留原有全部用例，只能增加或修改，不能删除；相应守卫另行实现。
- 已合入的 E2a 代理通道代码由另一个 PR 删除；E2b PR #57 已关闭。阶段 E 以 E1 人工通道和 E3 撞底座衔接收尾。历史设计与已完成试用保留为记录，不再作为目标行为。

## 理由

- 底座变动通常是依赖升级、CI、配置等小改动，人实现的成本低。
- 让代理修改受保护的底座，会主动打开最难防守的边界。StoryLoop 不是沙箱；在这一威胁模型下，继续采用代理路线只能不断叠加防护。E2a 经八轮以上审查仍未收敛。
- 目前没有必须让代理实现底座的真实需求信号。保留人工通道及判据用例完整性，比继续扩展代理通道更符合当前需求。

## 代价

- base 实现由人承担；既有 E2a 代码需要单独移除。判据路径的用例保留守卫尚未落地，在交付前不能宣称这条替代规则已由引擎强制执行。
- 本决定取代架构收敛设计 §4.2 的上述三条要求；底座专属写权限、全量回归、构建、人工验收和 E3 衔接不变。
