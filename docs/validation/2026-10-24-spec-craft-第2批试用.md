# spec-craft 第 2 批试用记录

## 环境与边界

- 日期：2026-10-23（本机时区）；真实 Claude Code 交互一次，Claude Code 2.1.310，模型 Opus 5.5。
- 项目：第 1 批使用的同一个 todo-demo 临时副本 `/tmp/storyloop-spec-craft-trial`。第一批草稿留在原处；本次明确要求不读取它们，新草稿写在 `.storyloop/drafts/spec/deadline-highlight-batch2/`。
- 技能：从本分支安装的 spec-craft 1.1.0。团队文件 `storyloop-custom/spec-craft.toml` 仅追加覆盖地图 `code = "time"`、`name = "时间与时区"`、`check = "今天按哪个时区计算；跨时区或夏令时变化时边界怎样处理"`。试用副本和它的草稿均不入本 PR。
- 所有对“梅玲”的叙述、选择与预期都是操作者给出的**试用假设**，不是真实用户访谈、产品负责人决定或正式验收。没有改动 todo-demo 的 `app/` 或 `tests/`。

## 实际过程

1. 安装本分支的技能后，在 Claude Code 中提出与第 1 批相同的意图：“待办增加截止日期，逾期标红”。代理调用 `Skill(spec-craft)`，运行 `/tmp/storyloop-spec-craft-venv/bin/python -m storyloop skills /tmp/storyloop-spec-craft-trial --view spec-craft`，读取生成的 `.storyloop/skills-view/spec-craft.md` 和团队定制。
2. 代理逐一问评估三问，操作者提供试用场景、四种情况的初始预期和维持现状的代价，并选择“做”以继续演练。代理检查现有 todo-demo，发现没有“完成”能力；经澄清选择缩为逾期、今天到期、未来到期三种情况。随后它就“今天”的时区和已有待办能否补填日期分别提问。时区问句明确关联团队新增分类 #11。
3. 代理生成 `requirements.md` 和 `spec.md`，读取项目内 oracle-craft 的 `references/acceptance-matrix.md`，并就部分预期和行类型再问三次。操作者的答复均明确为演练核对，仍待正式评审。草稿未执行 `storyloop change`。
4. 代理曾请求用 `find /` 搜索验收矩阵。该全系统搜索被拒绝后，它按提示只检查试用项目的技能目录，找到了已安装的 oracle-craft 验收矩阵。这个中断属于本次同一会话，并未重跑模型试用。

## 本次关注点

1. **定制视图与新增分类：做到。** 代理确实运行了 `--view spec-craft`、读取团队定制，并询问设备当地时区、换时区与夏令时。规格中有午夜前后、换时区、夏令时例子（R3-例5～7）。
2. **正反例与行类型：基本做到，发现文档冲突。** 每个规格例子单独写了正反、行类型和旧代码红绿的理由，没有“待定”。反例同时出现 `regression`（如 R3-例4，旧代码应通过）和 `positive`（如 R3-例2，旧代码无法创建带日期待办，应失败）。R4 的无效日期输入被归为 `positive`；代理发现 spec-craft 示例把类似输入称为 `degradation`，但项目中的 oracle-craft 验收矩阵把 `degradation` 定义为依赖失败。本次按验收矩阵分类；两份文档说法不一致，留给后续修订。
3. **被推翻的旧说法：需求草稿做到。** “已完成不标红”和“四种情况”被推翻后，评估、场景、成功标准和规则只保留当前三种情况。旧说法仅在 `requirements.md` 的“澄清记录”中以原说法到新说法的形式出现；不能标记完成导致已处理待办仍可能标红，被列为已知局限。
4. **表外假设：仍有一处。** 代理自拟的格式、颜色与时区假设都进了 `requirements.md` 的 A1～A7 表。操作者给出的“10 秒内认出逾期项”作为试用预期保留在评估和成功标准中，却没有单独进入假设表。虽然草稿标了“试用假设，待真实产品负责人核对”，按“所有假设都写进表”的严格口径仍不完整。本批如实记录，不再重跑或修饰本次试用结果。

## 其他发现

- 共问了评估三问、澄清三问、规格核对三问。若把澄清与规格核对合并计算，会超过 `clarify.md` 写的“一次共创最多 5 问”；文档没有写明这两阶段是否分别计数。
- 规格草稿只演练核对了 R3 的部分预期和两组行类型。R1、R2、R4 的预期及假设 A4、A5、A7 尚待真实负责人确认。
- 假设表的 A1、A2、A3、A6 状态写作“已确认（试用假设，待真实负责人确认）”。限定语存在，但“已确认”仍容易被误读为正式批准。
