## 发现的问题

1. **（缺陷，自阶段 D 起存在）命令适配器握手的 `{python}` 解析不一致**：`capability_protocol._argv`（约 117 行）用 `shutil.which("python")`，而 `agent_transport` 实际调用用 `sys.executable`。本机 PATH 上的 python 是另一个 venv，握手时包装脚本 `import storyloop` 失败 → reviewer `known:false`，且无任何提示（`adapters check` 也只显示 `known:false`，不给原因）。
2. **（缺陷/提示）代理模式下 BASE_REVIEW_REQUIRED 的提示错误**：已配置并握手成功的跨厂商审查，停点仍写“等待另一名人员审查底座候选提交”，next 与 options 指向 `storyloop base-review --verdict pass`（人工审查）；实际只需再 `storyloop run` 即触发代理审查。照提示操作会让人代替了本应自动进行的跨厂商审查。握手未知（vendor 缺失）时的行为未在本次验证，需确认是否按设计 fail closed。
3. **（提示）DESIGN_APPROVAL_REQUIRED 停点两套命令互相矛盾**：next 为 `storyloop base-design-approve --plan-id`，而 stop.options/resume 为功能变更用的 `storyloop approve --design '<plan-id>'`。
4. **（体验）方案内容不在停点输出中**：人需到项目内 `.storyloop/state/base-designs/<id>.json` 查看，且中文被 `\u` 转义，不便审阅。
5. **（泄漏）测试在系统临时目录留下大量独立 worktree**：`storyloop-agent-wt` 下 2198 个目录、701 个文件（含完整检出与 `.git`），最早 2026-10-26 17:04，来自测试套件运行；本次试用自身的 worktree 已清理。测试应把临时根指向各自的临时目录并清理。
6. **（成本）** 一次底座小改动约 6 分钟代理时间；握手缓存变化引起的重来额外再花一轮 design+implement。
