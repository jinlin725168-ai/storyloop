## 执行边界与授权归属

固定引擎为 PR19 已合入 `f171444cd46c151c4e28d304116526ef767dab41` 的源码树；实际隔离安装提交 `1e5eda0` 与它的树完全一致，运行中未升级引擎。

在独立普通 clone、独立源分支和新建的 `1.0.0` 控制面执行，沿用 RuoYi 既有受保护 settings。没有搬运或改写原仓库 `1.0.19` 状态，因此不是旧控制面迁移，也不是 T4 新接入模板在真实 RuoYi 上的验证。本地引擎合并只发生于隔离源分支，不自动提交原仓库 main。只使用专用本机测试容器及既有执行器创建的临时数据库，没有访问生产数据或改变业务 schema。

用户原话“直接使用红魔这个品牌来替换，其他按你的建议来”提供了本轮范围授权。生成合同和方案由协调者核对后代办批准；软件写 `actor=user`，不能证明用户另行逐字签收，也不能据此测量人工工时。

首次外部角色调用被自动审批拒绝，原因是可能发送私有源码。协调者只读证明目标仓库 PUBLIC、起始提交已公开，使用不含私有历史的新控制面和限定规范，再经自动复审批准后执行。没有发送 `.env`、真实凭证、数据库配置或业务数据。

早期 Claude 调用采用 safe-mode、strict-mcp-config 和 restricted；第二轮设计遇到订阅会话额度限制，返回 AGENT_UNAVAILABLE。无购买额度或覆盖停点。无仓库内容的 Codex CLI 最小连通检查通过后，切换到引擎已有 Codex 适配器。使用 ignore-user-config、project_doc_max_bytes=0，关闭插件、记忆和多代理，保留角色写权限边界与所有 Judge 门。没有设置模型覆盖，不能声称 strong 档模型映射已实测，也不能把全程称为单一适配器自然成功。

## RED、失败与正式纠偏

### 准备阶段

linked Git worktree 初始化遇到 FileExistsError；Judge 原本就不支持 `.git` 指针文件，本次改用普通 clone。独立引擎修复 [PR20](https://github.com/jinlin725168-ai/storyloop/pull/20) 在写入前拒绝外部 Git 控制目录，没有实现半套 worktree 支持或放宽安全检查。其 core542项（538通过、4跳过）及远程 Linux/Windows CI通过；本次仍使用固定旧引擎。

前端基线首次受只读位置的 Vite 缓存写入限制，转入独立 clone 后13项通过。既有离线依赖恢复后，运行配置的 Maven 单元命令去掉 `-q`，正确识别74项；Vitest 加 `NO_COLOR=1` 避免 ANSI 影响计数。仓库无 `*IT.java`，原集成命令空执行仍退出0，独立配置明确标 MISSING，没有删除真实测试或修改受保护 settings。最终基线 unit87项、checks通过，系统冒烟为13项 unittest 加2项 Playwright。

### 首轮001：保留失败，不冒充闭环

真实 product 首次响应引用不存在的 `setting.title`，被引擎拒绝。协调者核实实际 `setting` 声明并更正；同时把耦合常量/源码文本的验收方法改成真实 UI 行为并同步 heavy 分类。原响应保留，修订不是新的自然模型成功。heavy 为3故事、7个既有文件、2个新业务文件；字面引用启发式156不是真实调用图或用户数。

合同 `140a314` 上品牌 Playwright 原生9项断言失败、登录回归8项通过，证明 RED。方案 A 摘要 `30ad1d319e68d819cc79b44db599ab8f29dab5d700915005f9ba8fda6c675cee` 由协调者依据既有授权批准。一致性审查无阻断，但记录了 method.commands 与 manifest 不一致及动态标题关闭语义遗漏。

首轮特征化以源码结构断言为主，前端45项通过。新测试的两个 `?raw` 默认导入随后被 lint 拒绝；这是本轮引入的问题，不能归于原源码。角色声称品牌9/9通过时 Judge 尚未完成，不能称首轮验收成功。

协调者在 Judge 期间错误地从候选目录启动 browse，工具新增 `.gstack` 和 ignore 条目，触发 WORKSPACE_TAINTED。移出工具状态、仅恢复工具新增忽略行并停止该进程后，正式 reset 留理由。这是协调者失误，不是引擎故障。之后浏览器全部从 `/tmp` 使用独立状态文件运行。

依据合同命令和标题兼容语义缺口，正式 supersede 001→002，业务范围不变，原状态保留 SUPERSEDED；原实现留在 stash/feature 历史，源分支回到原始基线。未手改锁定测试、添加虚假导出、改阈值或复用前轮 GREEN。首个002批准因残留未跟踪状态被 clean-source 拒绝，移出残留并重跑 READY 后才继续。
