# 验收矩阵的行类型

| 行类型 | 实现前 | 写什么 | 反例 |
|---|---|---|---|
| positive | 红 | 目标行为 | 只断言接口返回 200 |
| degradation | 红 | 依赖失败时明确失败、主流程不受影响 | 依赖挂了静默返回空列表 |
| unknown_state | 红 | 加载中或读取失败时不等同于否定（"未知不等于不支持"） | 元数据没加载完就判"不支持" |
| form_parity | 红 | 同一能力的不同用法都覆盖（独立应用与工作流节点） | 只测了一种入口 |
| regression | 绿 | 既有契约不变（字段、格式、校验） | 为了让新字段通过放宽了旧校验 |
| state_preservation | 绿 | 已保存状态"载入 → 交互 → 保存"后，除目标字段外完全相等 | 只断言新字段，没比对其余字段 |
| non_goal | 绿 | 没做的事不被宣称为已支持 | 报告里写"支持按工具统计"而其实没做 |

规则：

- 一个测试只覆盖同一种"实现前状态"的条件：应红的和应绿的分开写。
- `oracle_class: auto-heavy` 的条件写进 `tier: heavy` 的测试（端到端、浏览器、长时间）；其余写进 `tier: fast`。
- 断言值本身，不只断言字段存在或非空。
- 集成判据用真实依赖，不用 mock 顶替。
