# 八份文档的覆盖骨架（质量约定 1）

固定八文件，允许附加知识正文；不因缺信息删覆盖项。每份开头记 BASE 版本/source_head、实际观测完整 SHA、工作树状态、日期、技能 1.1.0、约定 1；BASE 元数据不可安全核实时写待确认。事实表使用 [source-and-sampling.md](source-and-sampling.md) 的 ID、来源状态、核验结果、来源与限制；不要用一个章节的来源替代多项事实的证据。

章节可改名、合并，覆盖项必须可定位。不适用写理由及探查范围；未查清写待确认。没有 HTTP/前端/数据库的库不能为填表虚构服务、账号或菜单。图使用 Mermaid。

```markdown
## 八文件索引及附加正文

运行单元 / 身份权限 / 行为开关 / 贡献规范 / 测试身份 / 基线信息 / 需求路由
## 推断、待确认、冲突与未覆盖项
## 抽检记录
完整候选清单及 SHA-256 / 单次随机种子 / N、D、样本量、规则版本 / 样本 ID
每样本：重新打开的来源、结论、相符/不符/无法核验、原因、修正及原失败复核
## 定向核对

本次范围 / 自检者与独立复核者（未做写未做）/ 下次触发 / 未完成事项
```

索引需与文件一致，七类映射指向具体节。候选覆盖所有正文事实、附加正文；不重复 README/errata。不能只列样本不列完整候选；无工具算摘要则标抽检未完成。仅自检不得称独立验证。空白为空时限定“本次已登记范围内无”。

## architecture.md：机制、身份与开关

```markdown
# 架构与运行机制
## 技术栈与版本：构建文件依据
## 启动/调用：入口、初始化、安全配置定义及消费代码
## 真实调用链：HTTP/CLI/库，适用的校验、返回与异常

## 前端机制、环境与运行方式：适用项及未知部署状态
```

不打开环境/凭证/秘密运行配置；用公开示例、键定义和消费代码说明机制。代码默认行为与部署实际值分开，未知部署值写待确认。没有身份系统时不能虚构“匿名管理员”。

## capabilities.md：实际行为与活规格

```markdown
# 能力清单
## 上游自带：能力、入口、可复用点
## 本仓库实际行为：代码/测试定义证据，不等同已运行测试

## 差异与依赖：代码/规格矛盾、未实现与未知
```

代码说明“现在如何”，活规格说明“应当如何”；冲突列两侧证据、影响和待裁决项，不用一侧覆盖另一侧。不重述规格全文。

## building-blocks.md：实际可复用资产

```markdown
# 可复用积木
## 后端/库：名字、路径、用途、典型调用
## 前端：真实组件/工具或不适用
```

每项有可找到的路径和可复用理由。不能拆一个函数凑多项，也不能把规划工具记成已存在。

## testing.md：测试、验收与身份隔离

```markdown
# 测试与验收基础设施
## 单元/集成测试：位置、框架、命令、筛选、默认跳过
## 前端测试：实际入口或不适用
## 验收生命周期：构建、启动、就绪、临时数据、运行与清理
## 测试身份：角色别名、fixture 来源、创建/重置/清理及隔离
## StoryLoop 回归命令与实际覆盖：安全的已知元数据
## 已知限制：跳过、开关、平台差异、未运行项
```

测试定义和测试运行证据分开；无执行记录不能说通过。身份机制只描述角色别名和 fixture，不读取真实账号、密码、token 或 PII。无身份系统写有范围依据的不适用。
