# 八份文档的章节骨架与质量标准

每份 = 章节骨架 + 质量标准。章节可按仓库裁剪，质量标准是验收底线。所有文档开头一行写"对应底座版本：x.y.z，生成日期"。

## README.md

```markdown
# 底座知识库
对应底座版本 / 生成日期 / 生成方式（storyloop survey 或交互式）
## 怎么用
- product：先看 capabilities.md，不重复建设，修改既有需求沿用旧标题
- implement：先看 extension.md 和 building-blocks.md
- smoke：先看 testing.md 和 building-blocks.md 里的验收客户端
- review：对照 extension.md 与 building-blocks.md
## 文档索引（八份，一句话用途）
## 已知空白（[待确认] 汇总）
## 什么时候刷新
```

质量标准：索引与实际文件一致；空白列表不为"无"除非确实没有 `[待确认]`。

## modules.md

```markdown
# 模块组成
## 一、模块清单        # 表：路径 | 职责 | 对外提供 | 依赖
## 二、依赖方向        # mermaid 图 + 文字：跨模块调用的唯一途径
## 三、可变区与底座    # module_roots 里哪些是业务、哪些是上游；integration_paths 列表
## 四、前端结构        # 目录职责（api/views/components/store/router/utils/types）
```

质量标准：每个模块一句话职责；依赖图能看出分层；标出禁止的依赖方向。

## architecture.md

```markdown
# 架构与运行机制
## 一、技术栈与版本    # 从构建文件读出，不猜
## 二、启动            # 入口、配置文件与 profile、启动时的初始化
## 三、请求链路        # 过滤器 → 认证 → 权限 → 参数校验 → 业务 → 统一返回 / 异常处理，每步给类名
## 四、数据访问        # ORM、分页、多租户、逻辑删除、审计字段填充、事务
## 五、横切能力        # 缓存、消息、定时、文件存储、加解密、日志、幂等
## 六、前端运行机制    # 请求封装、路由生成与权限、字典、状态管理
## 七、环境与运行方式  # 本地依赖（数据库、缓存）、端口、profile 的含义；配置只写键名和位置
```

质量标准：能回答"一个新接口从进入到返回经过哪些环节"；不出现任何配置值。

## extension.md

```markdown
# 扩展新功能机制
## 一、新增一个业务表的完整功能   # 分层表：层 | 文件 | 命名约定 | 参考实现路径
## 二、菜单与权限                 # SQL 模板、权限串格式、菜单 ID 约定、前端指令
## 三、前端页面                   # api/types/views 的写法、路由如何出现、字典与提示
## 四、修改既有功能               # 改字段、改接口、加筛选各碰哪些文件
## 五、代码生成器                 # 模板路径、生成物与手写的差异
## 六、禁止事项                   # 不能改的底座、不能直接依赖的模块、不能绕过的机制
## 七、参考实现                   # 一个完整例子的路径列表，可照抄
```

质量标准：没接触过仓库的人照第一节能列出新增功能要动的全部文件。

## api.md

```markdown
# 接口清单
## 一、约定            # 前缀、返回结构、错误码、分页参数、权限串格式
## 二、按模块的接口    # 表：方法 路径 | 用途 | 权限串 | 实现类
## 三、上游系统能力    # 用户、角色、菜单、字典、部门、文件、日志等的路由前缀
## 四、前端 api 封装   # 目录与命名
```

质量标准：每个接口有实现类；权限串与代码一致。

## capabilities.md

```markdown
# 能力清单
## 一、上游自带        # 每个能力一段：名字、入口路径、可复用点
## 二、本仓库已实现    # 以 openspec/specs/*/spec.md 为准：能力名、需求标题列表、入口路径、对应变更
## 三、能力之间的关系  # 哪些能力被别的能力依赖
```

质量标准：第二节与活规格一一对应；不重述规格细节。

## building-blocks.md

```markdown
# 可复用积木
## 一、后端            # 基类、工具类、通用服务；每项：名字 | 路径 | 用途 | 典型调用
## 二、前端            # composables、组件、工具；同上
## 三、验收            # 验收客户端、冒烟执行器、UI 回归资产、self-test
## 四、什么时候不该自己写  # 常见重复实现的清单（字典查询、分页、导出、文件上传……）
```

质量标准：每项能直接找到路径；第四节至少列出五个"别自己写"。

## testing.md

```markdown
# 测试与验收基础设施
## 一、单元与集成测试  # 位置、框架、运行命令、标签或 profile 筛选、默认跳过项
## 二、前端测试        # 框架、位置、运行命令、缺什么（例如没有组件测试库）
## 三、验收            # 冒烟执行器如何跑应用、临时数据、端口、验收客户端、UI 回归资产
## 四、回归命令        # StoryLoop settings 里的 test_commands 与它实际跑到什么
## 五、坑              # 已知会静默跳过、需要额外开关、平台差异
```

质量标准：运行命令从仓库配置推出；明确"默认会被跳过的东西"。
