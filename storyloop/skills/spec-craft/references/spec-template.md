# 规格文档模板

规格按规则一块一块写。每块包含临时编号 `R1`、`R2`……（正式 ID 由 StoryLoop 分配）、EARS 句式与正文、至少一个正例和一个反例。每个例子分别写所属规则、正反、行类型和 Given、When、Then。行类型引用 `oracle-craft/references/acceptance-matrix.md`，按旧代码上的预期红绿判定，不要在这里另建表。

接口与数据约束只写外部可观察的部分，不写类名、框架或实现步骤；例如“日期输入须为有效日历日期”，不要写数据库字段类型。重档再加消费端矩阵，列明每条规则由哪个可见界面或外部调用使用。

## 完整小例子

### R1：逾期高亮

- EARS：状态驱动。
- 规则：`WHILE 待办未完成且到期日早于今天，THE SYSTEM SHALL 把它标红。`
- 正例：所属规则 R1；正反：正例；行类型见验收矩阵的 `positive`；Given 今天是 2026-10-24，梅玲的“缴费”到期日为 2026-10-20 且未完成；When 她打开待办列表；Then “缴费”标红。
- 反例：所属规则 R1；正反：反例；行类型见验收矩阵的 `regression`；Given 今天是 2026-10-24，“缴费”到期日为 2026-10-20 且已完成；When 梅玲打开列表；Then “缴费”不标红。
- 外部可观察约束：日期按人确认的当地日历日比较。

请人核对例子中的预期结果，尤其是“到期日等于今天”和“已完成”的边界。
