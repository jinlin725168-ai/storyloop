# 正例与反例

每条规则至少一个正例、至少一个反例。反例写“规则被违反时应当发生什么”，不是把正确结果简单改成错误结果。例子的预期结果由人核对，AI 只提出草稿。

每个例子标所属规则和行类型；行类型沿用 `oracle-craft/references/acceptance-matrix.md` 的验收矩阵，**只引用它，不复制行类型表**。反例通常是其中的 `degradation` 或 `unknown_state` 行；最终类型依实际场景选。

Given 使用具体数据：数字、带引号的文本、日期或 ID；When 写确切动作；Then 写外部可观察的结果。好：“Given 梅玲有待办‘缴费’，到期日 2026-10-20，今天是 2026-10-24，状态未完成；When 她打开列表；Then ‘缴费’标红。”坏：“Given 一个用户有一些待办；When 查看；Then 正确显示。”坏例没有具体数据，也无法让人核对结果。

反例要覆盖边界或异常，如：“Given 同一待办到期日为空；When 梅玲打开列表；Then 它不标红，也不被当作过期。”若“空日期”是否允许尚未确定，先标为假设并请人确认。
